1. 任务与方案概述
本方案面向「基于大模型的多模态视觉理解与推理」赛题：给定同一场景的可见光（visible）、红外（infrared）、深
度（depth）三模态图像与一条自然语言查询（如  "A  squatting
person"），模型需输出查询目标在图像中的归一化边界框（bbox） [x1, y1, x2, y2]（取值范围 0~1）。
方案采用预训练多模态大语言模型 Qwen3.8-27B-Instruct 零样本推理路线：
   * 不训练、不微调，直接利用大模型已有的视觉 - 语言对齐能力完成开放词汇目标定位；
   *  三模态图像以分图（split）方式组织为多模态输入，配合数据预处理的多模态协同策略提升低光  /
红外场景鲁棒性；
   * 模型以 multi_box 模式一次生成多个候选框，经解析与后处理输出每查询一个归一化 bbox；
   * 推理结果再经多产物共识投票后处理（§3.5）消除单次解码的系统性偏差，提升定位一致性。
2. 数据集
本方案仅使用赛事官方提供的测试集进行推理，未使用任何外部训练数据（零样本推理，无训练环节）。
项目 内容
图像规模 1295 张场景图像（三模态各 1295 张对应文件）
查询规模 5690 条查询（多查询 / 图）
模态 visible /infrared/depth（三通道，depth 为深度图）
输入格式 Images/visible、Images/infrared、Images/depth + queries.json
输出格式 Query ID -> {visible, infrared, depth, query, bbox}

3.2 多模态输入与预处理（src/data/）
   * RGB 归一化：uint8 → float32 / 255.0；
   * 红外去噪：红外三通道视觉特征高度一致，转灰度后中值滤波去除椒盐噪声，再恢复三通道；
   * 深度离群剔除：深度值超出有效范围（0 ~ 19999 毫米）视为无效并剔除；
   *  低光多模态协同：可见光亮度低于阈值（low_light_threshold:  60）时，以门控融合（fusion_gate_scale:
30.0）引入红外 / 深度特征增强可见光（fusion_ir_weight: 1.0、fusion_depth_weight: 1.0）；
   *  输入组织：multimodal_input_mode:  "split"——  可见光  /  红外  /
深度分图送入视觉编码器，保持三模态空间对齐。
3.3 推理（src/inference/、src/models/qwen3_vl.py）
   *  模式：multi_box（单图一次生成多个检测框），enable_thinking:
false（关闭思维链输出以提速），max_new_tokens: 1024；
   *  视觉特征缓存：feature_cache:  true、cache_max_entries:  4——
同一图像的多条查询共享视觉特征，显著减少重复前向计算；
   * 文本 - 检测框匹配：解析模型输出坐标 → matcher 做文本标签与检测框匹配 → bbox 归一化；
   *  序数链约束  chain_enforce:  "off"（跨查询一致性约束默认关闭）、深度先验  enable_depth_prior:
false（本次提交未启用）。
3.4 后处理与提交格式（src/postprocess/、make_sub.py）
   * bbox 归一化到 [0,1]，坐标 round 至 4 位小数；
   * 非法 / 缺失输出回退到占位框 [0.49, 0.49, 0.51, 0.51]；
   *  每查询条目附原始三模态路径与查询文本，形成  submission.json；zip  压缩（内部文件名
submission.json）供平台提交。
3.5 多产物共识投票后处理（scripts/consensus_pick.py）
问题：单次解码得到的主件，在其与其它独立解码结果不一致的位置上存在系统性偏差；此类位置占比不高，且单一模
型无法自证孰是孰非。
办法：引入多产物共识投票。
   *  以主件与参照件（另一套独立解码结果）的真分歧位（两框互  IoU  <
0.5，即两套结果指向不同区域）为候选改动面；两框互 IoU ≥ 0.5 的同侧位置不构成有效改动，一律跳过；
   * 对每个候选位，由 32 套独立产物逐个判定其更接近主件还是参照件，分别累计两侧票数；
   * 仅当「主件零票、参照件满票」时采纳参照件框，其余候选位一律保持主件。
阈值确定：由投票一致性原理确定——只有当主件在候选位上未获得任何支持票、参照件获得全体支持票时，才判定该
分歧源自主件的单侧偏差，此时采纳参照件；一旦出现任何异见票，说明该分歧存在非单侧成因，一律保持主件不动。
该策略保证每一处改动均由全体独立产物的一致意见支撑，不引入低置信扰动。
实现：scripts/consensus_pick.py，投票池  consensus_pool.json.gz（32
套独立产物的坐标，随包分发以保证离线复现）；输出 zip 固定时间戳，同输入必得同 SHA256。
