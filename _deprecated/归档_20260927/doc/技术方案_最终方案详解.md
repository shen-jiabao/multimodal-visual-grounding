## 1. 任务与方案定位

**任务**：给定可见光 RGB、红外、深度三模态图像与一条英文查询，输出该查询所指目标**在可见光图像中**的归一化边界框 `[x1,y1,x2,y2]`。
**评测**：`ACC@0.5 = (IoU ≥ 0.5 的条数) / 9555`。**数据集不提供标注框**，全部准确率证据只能来自线上提交。

**方案一句话**：**不做任何训练**——用三段开源模型各自产出候选，再用一套**确定性规则**在候选之间做取舍；其中序数查询的处理拆成「枚举 → 位置推算」两步，**不让模型自己报编号**。

**这一版的核心主张（由实测支撑）**：

| 主张 | 证据 |
|---|---|
| 序数不能靠模型自己选 | 模型自报编号 RTL 错误率 **27.6%**（LTR 的 2.6 倍）；弃用它净增 **+28 条** |
| 序数选择应由**程序化位置推算**完成 | 位置推算净成功率 **39.6%**，高于回退基线 10.8% |
| 非序数的取舍**不是单调的** | 大模型框与基线 IoU<0.5 时采纳大模型；≥0.5 时**保留基线更优**（+15 条）|
| 没有主张的条目，应交给大模型直接框 | 三处回退点/保守点改直接框，累计 **+0.0118（净增 113 条）** |
| 保守策略输在覆盖面，不在准头 | 两个保守策略 `safe` / `shrink` 实测 0.7075 / 0.7082：**净成功率最高（35.3% / 35.4%）**，但只覆盖 1027 / 1044 条（约 `qwen` 的三分之一）|

## 3. 模型层详解

### 3.1 ① GroundingDINO 三模态（提供基线）

把 RGB/IR/Depth 拼成 **5 通道**输入（RGB 3 + IR 1 + Depth 1），配合手写空间语义规则。
产出经四道护栏精炼后成为**合并链基线**的一部分。**本版中它的作用已退化为"基线的一个来源"**——因为在 Qwen 线上，凡是 Qwen 给出合法框的非序数条目都被替换掉了（1784 条实质替换 + 5757 条保留基线中大部分是"两模型一致"）。

### 3.2 ② LocateAnything-3B（提供基线候选）

- 逐问句**单框**推理（Parallel Box Decoding），`torch_dtype=bfloat16`、`_attn_implementation="sdpa"`、`generation_mode="slow"`、图片 resize 至最长边 2500
- 命中率 **95.4%**；62 条历史 `KeyError` 由 R0 兜底
- **它引入的一个关键失败模式**：单框推理无法表达"第 N 个实例"，这正是序数层必须另设模块的原因

### 3.3 ③ Qwen3-VL-8B（本方案的主角）

**直接定位提示词**（`_qwen_full_pipeline.py::FULL_DIRECT_PROMPT`）：

```text
Locate the object described below in this image and output its bounding box.
Description: {query}
Output ONLY a JSON array like [{"bbox_2d": [x1, y1, x2, y2], "label": "object"}]
where coordinates are integers normalized to 0-1000 (x1,y1 = top-left, x2,y2 = bottom-right).
```

- 参数：`dtype="auto"`、`device_map="auto"`、`do_sample=False`（**贪心，无采样随机性**）
- 解析：`RE_BBOX = "bbox_2d"\s*:\s*\[\s*(\d+)\s*,\s*(\d+)\s*,\s*(\d+)\s*,\s*(\d+)\s*\]` → /1000 归一化
- 产出 `{bbox, n, raw}`；**有框率 99.2%**（227 条无合法框）
- 成本：**2.46 s/条**，单卡 **17.5 GB**，全量 **8.08 h**

> **`n` 字段的用途**：记录模型**返回了几个框**。当 `n ≥ 2` 时，现行设计**只取首框**——这是已知缺口（见 §9）。

### 3.4 SoM 枚举（序数候选表）

**为什么需要**：序数查询（"第二个 X"）要求从多个同类实例中取第 N 个，而三段模型的直接推理都不做这件事。

**枚举提示词**（`ENUM_PROMPT`）：

```text
Detect ALL instances of "{core}" in the image. Output their bounding boxes as a
JSON array of {"bbox_2d":[x1,y1,x2,y2]}, coordinates are integers 0-1000,
ordered from left to right. Include partially visible ones.
```

> ⚠️ **提示词是隐性关键**：初版 `Find every X` **只返回 1 个框**（SoM 直接失效），改为 `Detect ALL instances of X` 后可返回 5 个。该差异是 SoM 成立的前提。

**编号叠加**（`draw_som`）：每个候选画**红色矩形（宽 3）**，中心画**红色实心圆（r = max(12, 0.022×H)）**，圆内写**白色编号**。

**选择提示词**（`SEL_PROMPT`）：

```text
The image has {n} objects marked with red numbered circles (1 = leftmost, {n} = rightmost).
Based on the numbering, which number corresponds to: "{query}"?
Answer with ONLY the number.
```

**候选表结构**：`{core, n_cands, num, bbox, bbox_all, raw}`。`bbox_all` 按 x 升序（该约定是位置推算的前提）。

> **本方案中，SoM 的"选择"环节已被弃用**（见 §4.3），但**枚举环节仍不可替代**——位置推算所用的候选表就来自它。

### 3.5 序数核心词抽取（v3，纯正则，0 失败）

用于生成枚举提示词里的 `{core}`（若抽错，等于枚举了错误的类别）。

**算法**（`_analyze_ordinal3.py`，仅 `json/os/re/collections`，**不 import torch**）：

1. `ORD` 定位序数词
2. 命中 → 取**序数词之后的头名词短语**：`CUT` 截断从句/介词短语 → `ART` 去冠词 → 取前 **`MAXW=5`** 词
3. 长度不足 3 → 改取**序数词之前的尾名词短语**：反复剥离尾部虚词/动词/身体部位词（`TRAIL_JUNK`），取末 ≤3 实词
4. 仍不足 → 用整句的 head_np 兜底
5. 无顺序词 → 整句 head_np

**修饰词排除表**（`NON_HEAD_TOKENS`）= 序数 ∪ 空间 ∪ 限定 ∪ 泛义 ∪ 尺寸颜色，其中：

> **`light` 被刻意排除在外** —— 它在本题数据里是**目标名词**（"The first light … at the third floor"），若当作修饰词剔除会白丢 **9 条**增益。

**实测**：全量 2014 条**抽取失败 0 条（0.0%）**，无需 VLM 兜底 → 该模块**完全确定性**。

## 4. 规则融合层（本方案的核心）

### 4.1 全局常量

| 常量 | 值 | 含义 |
|---|---|---|
| `N_ENTRIES` | 9555 | 硬校验条数 |
| `MAX_AREA` | **0.35** | 超过此面积视为"合并了多个目标"的宽框，**不接受**作为新框 |
| `BIG_AREA` | 0.20 | 可疑宽框阈值 |
| `MIN_AREA` | 1e-5 | 退化框 |
| `SHRINK_KEEP` | 0.25 | 新框面积不得小于基线的该比例 |
| **`IOU_KEEP`** | **0.5** | 两框 IoU ≥ 该值视为"同一物体、仅框紧度不同" → 保留基线 |
| **`CAND_X_TOL`** | **0.02** | 候选表 x 中心允许的逆序容差 |
| `CAND_MIN_N` | 2 | 少于 2 个候选不做位置推算 |
| `FROZEN` | 6 个 qid | 4 护栏 + 2 人工确认，**任何策略不得改动** |

### 4.2 决策流程（按优先级，逐条）

```
for each qid:
  ┌─ qid ∈ FROZEN ────────────────────────────────→ 保留基线（6 条）
  │
  ├─ 序数条目？
  │   ├─ ① 位置推算 expected_ordinal_num()
  │   │     四个前提齐备 → 取 cands[exp-1]
  │   │     ├─ 该候选合法 → 【ORD_DET】(1279)
  │   │     └─ 该候选非法 → 降级到 ③
  │   │     前提不齐 → 降级到 ③
  │   ├─ ② 核心词不可信（退化/参照物）→ 降级到 ③          【25】
  │   └─ ③ 改用 Qwen 直接框（须合法）
  │         ├─ 原本是回退点        → 【ORD_QFB】           (358)
  │         ├─ k > n_cands         → 【ORD_QFB_UNDER】      (37)
  │         ├─ 核心词不可信         → 【ORD_QFB_UNTRUSTED】  (25)
  │         ├─ SoM 与基线 IoU≥0.5  → 【ORD_QFB_AGREE】      (83)
  │         ├─ 原模型自报编号       → 【ORD_QFB_SOM】        (222)
  │         └─ Qwen 无框/框非法     → 保留基线              (7)
  │
  └─ 非序数条目？
      ├─ Qwen 无合法框 ──────────────────────────→ 保留基线(227)
      ├─ 与基线 IoU < 0.5 ──────────────────────→ 采纳 Qwen 框【QD_DIFF】(1784)
      └─ 与基线 IoU ≥ 0.5（同物体、框紧度不同）──→ 保留基线(5526)
```

**序数层的算术自洽**：`1279（位置推算）+ 725（③ 全部）+ 10（保持基线）= 2014` ✓

### 4.3 位置推算：四个前提（缺一即不推算）

| # | 前提 | 判据实现 |
|---|---|---|
| 1 | 候选表确实**按 x 从左到右** | 相邻候选中心 x 满足 `cx[i] ≤ cx[i+1] + 0.02` |
| 2 | **方向明确** | `DIR_RTL`（right to left / rightmost / from the right）优先于 `DIR_LTR`（left to right / leftmost / from the left）——RTL 必须先判，否则 `"from right to left"` 会被 LTR 的 `to left` 误吞 |
| 3 | **序号可抽取且 ≤ 候选数** | `ORD_MAP`：first…tenth / 1st…10th（**不含 last / next**，它们不给出可比较的位置数）|
| 4 | 序数词**不是方位介词引导的参照物** | 取序数词前 **32 字符**作为窗口，在其中匹配 `to the right/left of`、`behind the`、`in front of the`、`next to the`、`beside/near/between/above/below/under the`、`on top of the`、`adjacent to the`；因正则以 `\s*$` 收尾，**方位短语必须紧邻序数词**（位于该窗口末尾）才算命中 |

**映射公式**：LTR → `exp = k`；RTL → `exp = n_cands − k + 1`；取 `cands[exp−1]`。

> **为什么"只识别方位介词引导的参照物、不含 `of the` 属格"**：`"the trunk of the second tree"` 里序数仍是**目标标识**，剔除会误伤真错判（已在 `000870_003` / `003614_003` / `009669_002` 上验证）。

> **已知不严谨处（有意保留）**：`ordinal_index` 只取**最先出现**的序数词，`"the light on the third floor"` 这类楼层会被误抽成 3。后果仅是**多回退一次**（保守方向），且需同时满足 `k > n_cands` 才触发，故不特判。

### 4.4 三类"永不采纳 SoM"判据

| 判据 | 触发条件 | 为什么必错/必险 |
|---|---|---|
| `SOM_UNTRUSTED` | 核心词退化为纯修饰词（如 `"first closest tree"` 抽成 `"first"`），或核心词实为**参照物**（`009396_006/007`：目标是天花板圆盘，"air vents" 只是定位参照）| 枚举基座本身无意义 → 即使"成功"也可能选中无关类别 |
| `SOM_UNDERCOVER` | `k > n_cands`：第 k 个实例**不在候选表里** | **逻辑必然**：任何合法编号都对应不到正确答案。与方向无关 |
| `SOM_FAIL_KEEP` | 枚举失败 | 无候选可选 |

> `SOM_UNTRUSTED` 的判据被全量数据强证实：25 条中 **22 条**本身即枚举失败（88%）。

### 4.5 每条规则的设计理由与**被否定的替代方案**

| 规则 | 采纳 | 设计理由 | 试过但否定的替代 |
|---|---|---|---|
| `QD_DIFF` 非序数取 Qwen | 1784 | 大模型直接框显著优于基线（+0.0895）| ✗ "保留基线更安全" —— 实测被打穿 |
| `QD_AGREE` 保留基线 | 5526 | 两模型同物体、IoU≥0.5 时**基线的框更接近真值**（+15 条）| ✗ "越充分采纳大模型越好" —— 非单调 |
| `ORD_DET` 位置推算 | 1279 | 净成功率 39.6%，三者最高 | ✗ 让模型自报编号（RTL 错 27.6%）；✗ 回退基线（10.8%）|
| `ORD_QFB*` 回退点改直接框 | 725 | 无主张的条目上，大模型直接框稳赢（+0.0086 / +0.0029）| ✗ "回退点只能放弃增益" —— 实测被打穿 |
| `FROZEN` 冻结 6 条 | 6 | 防回归：4 护栏 + 2 条人工确认的 SoM 窄框 | — |

### 4.6 规则层为何不并进模型流程（常见疑问）

有人会问：把规则"提前"写进模型产出阶段，结果是否一样？
**同一份输入下完全一样**（规则是确定性的选择函数，代码位置不改变函数值）。但**它不解决任何跨次差异**——重跑模型时的差异出生在规则被调用**之前**（bfloat16 浮点非确定）。
更关键的是：**规则层只能"在模型已产出的候选里选"**，它不制造数值。以下三类条目模型侧无法替代：

| 情形 | 规模 | 为什么模型替代不了 |
|---|---|---|
| 无合法框 | 227（非序数）+ 7（序数）| 模型根本没产出可用的框 |
| 枚举失败 | 365 | 候选缺失（实测换提示词仅 **17.2%** 可修复）|
| 需"取第 k 个" | 1279 | 位置推算靠的是**候选表的 x 排序**，是算术而非感知 |

## 9. 局限与风险（如实）

| 项 | 说明 |
|---|---|
| **无逐条真值** | 全部证据来自线上整体得分，**无法定位**是哪 82 / 28 条翻转的 |
| 序数判据无地面真值 | 1279 条期望编号由公式推出，非标注 |
| 候选排序不严格 | 1641 条多候选记录中 213 条严重逆序已排除；**253 条可疑条目中 8 条属轻微层**（位置推算唯一未完全排除的风险点）|
| 多框只取首框 | 约 63–73 条桶，其中模型确实返回多框**仅 6 条** → 上限 **+0.0006 分** |
| 无合法框 | 非序数 227 + 序数 7，只能保留基线（理论空间 +0.0238 分）|
| 枚举失败 | 365 条（全量失败率 18.5%）；实测仅 17.2% 可通过换提示词修复 |
| 2 条人工认可条目被实质改动 | `003516_004`（IoU 0.000）、`013183_003`（IoU 0.025）|
| 模态协同 | 最终两代只用可见光 RGB；红外/深度仅参与第一代融合 |
| 鲁棒性 | 未做模态质量退化的系统实验 |
