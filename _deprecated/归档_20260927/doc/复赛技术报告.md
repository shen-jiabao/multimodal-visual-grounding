## 4. 模型选型：8B vs 32B（同清单对比）

机器上现成部署着 vLLM 上的 Qwen3-VL-32B-AWQ，另有可下载的 8B。为比较二者，做了**固定清单**的 A/B 探针（30 条 = 15 direct + 15 序数，同一份 `/srv/output/probe_qids.json`）。

> 方法学教训：首次对比时两轮各自按"当时可读的图"筛选，导致条目集不同、结论无效。改为**显式清单**后才可比。

```
direct 出框        32B 30/30  |  8B 30/30
direct 一致性      一致(IoU>=0.5) 20/30  |  实质差异(<0.5) 10/30（IoU 中位 0.862）
序数枚举候选数一致  12/15
序数选中编号一致    12/15
速度               32B direct 2.31s / som 6.05s   ← 更快
                   8B  direct 2.69s / som 7.44s
```

**不依赖真值即可判错的证据**（"不同序数必指不同物体"）：

```
[8B] direct 矛盾  000085_003 vs 000085_004   IoU=0.993
   The second of three buildings ... -> [0.476,0.213,0.522,0.346]
   The third  of three buildings ... -> [0.476,0.213,0.522,0.347]
[8B] SoM 矛盾     000281_001 vs 000281_003   选了同一候选 num=2、同一框
[32B] 组内矛盾对数：0
```

**局限声明**：复赛**无真值**，30 条探针**无法算出 ACC**。上述只能证明"8B 有自相矛盾"，**不能证明 32B 更准**。

**决策**：选择 8B（与初赛 0.7827 判据链同模型同提示词，可复用已验证规则）。

## 8. LA 全量：探针与两个起跑前拦截的缺陷

### 8.1 探针（复赛数据，12 图 80 问句）

```
模型加载 5.5s | 加载后显存 7.77 GB（torch 口径）| 文本 attn = sdpa
单条平均 9.82s / 中位 9.63s / 最大 19.96s   ← 该值在并发下测得，被摊薄
命中率 96.2%（77/80）
框数分布 {1:72, 2:1, 3:1, 7:1, 12:1, 41:1}
无框 3 条均为显式拒答 <ref>…</ref><box>None</box>
```

全量 5690 条外推：并发下 15.5 h / 初赛记录 3.84s 对应 6.1 h / 折中 5.0s 对应 7.9 h。

### 8.2 缺陷一：`_locate_full.py` 丢弃了除首框外的全部框

原实现 `b = norm_bbox(boxes[0])`，只存首框。而融合的互印证规则需要全部候选才能去重与比对。**若漏改，LA 跑完 6–8 小时的产物无法执行既定规则。**
→ 改为落盘 `bbox_all`（含异常分支）。

### 8.3 缺陷二：`MAX_AREA` 被用错层次

`_fuse_qwen.valid_cand` 含 `MAX_AREA = 0.35` 上限，其注释明说这是"新框能否替换"的标准、"不能用新框的标准去否决存量"。融合脚本误把它同时用于**去重过滤**与**最终采纳**，导致：

```
000512_002 "Thin white horizontal wires"
  LA 41 个完全相同的框 [0,0.424,1,1]（同框刷满 256 token 的退化重复，耗时 19.96s 为全场最长）
  8B 独立给出 [0.0,0.417,1.0,0.997] → IoU 0.983（两模型高度互印证）
  → 双双被 MAX_AREA 判非法 → 最终输出 null（必然丢分）
```

→ **改用 `ordered`（只要求有序且在 [0,1]），`MAX_AREA` 退场**。其功能已被互印证规则取代：LA 若单独给出合并宽框而 8B 没有，`IoU < 0.3` 会自动弃用 LA。

### 8.4 取框规则（把"未验证假设"换成可核对的机器规则）

```
1) LA 多框先去重（IoU > 0.99 视为同框重复）
2) 去重后单框 → 采用
3) 仍多框 → 取与「对照答案」IoU 最高者
   对照答案：序数问句取 8B 的 SoM 框，非序数取 8B 的 direct 框
4) 最高 IoU < 0.30 → LA 该条不予采信，交回 8B
5) 无对照答案（8B 无框）→ 取面积最大者，规则名单独标记
6) LA 无结果/无框 → 用 8B
7) 两者皆无框 → 输出 null 并计数报警（不静默填充）
```

**规则 3 的依据（实测）**：LA 与 8B 的 **SoM** 结果对齐，而非与 direct 对齐：

```
000512_004  IoU(LA, 8B.direct)=0.000  |  IoU(LA, 8B.som)=0.651
000085_002  IoU(LA, 8B.direct)=0.000  |  IoU(LA, 8B.som)=0.951
```

这两条均为序数问句——8B 的 direct 在序数上本就不可靠（这正是管线要加 SoM 阶段的原因），而 LA 直接吃原始描述即可定位。

**干跑回测（5 条多框条目全部符合设计）**：

| 条目 | LA 框数 | 结果 | 说明 |
|---|---|---|---|
| `000512_002` | 41（面积 0.576） | LA 首框 | null 已修 |
| `000246_012` | 2 | **LA 第 2 框** | `boxes[0]` 反例已修 |
| `000246_001` | 7 | LA 第 2 框 | 与 8B 右缘吻合 |
| `000001_006` | 3 | LA 首框 | 与 8B IoU 0.957 |
| `000085_001` | 12 | LA 被规则 4 弃用，交给 8B | 语义分歧 |

并核验：**LA 有框却最终 null 的条数 = 0**（无静默丢失）。

## 10. 45 条无框：结构性发现与处置

**真实数字：45 条**（不是干跑时被数据不完整主导的 4090）。与产物一致性吻合：`direct 有框 5645` → `5690 − 5645 = 45`。其中**序数仅 1 条**，涉及 44 张图。

### 10.1 结构性发现：这些问句问的是热成像内容，而管线只喂了可见光

查看 45 条的原始输出，发现大量**显式拒答**（`There is no object in the image that matches the description …` / `There are none.` / `[]`），且问句内容呈现明显聚集：

```
001555_009  The deer appearing as a bright warm blob in the thermal image standing alone …
001576_002  The animal emitting a strong heat signature visible in the thermal spectrum
001653_004  The warmer thermal signature corresponding to the person's body in the thermal …
001688_004  The warmer thermal signature corresponding to the person's body in the infrared …
001835_005  The bright heat signature of the person standing in the center of the thermal …
014673_007  The brightest warm heat signature moving along the road
```

量化：

| 项目 | 数量 |
|---|---|
| 全部 5690 条中，问句含热成像/红外语义 | **177 条（3.1%）** |
| 45 条无框中属于该类 | **12 条（27%）** |
| 热成像类中"有框"的 | **165 条** |

**机制判断**：`_qwen_full_pipeline.py` 只加载 `Images/visible/`。要求模型在一张 RGB 图上回答"热信号在哪"，它找不到就拒答——**这不是模型弱，是喂错了模态**。而那 165 条没有拒答、硬猜了一个框的，机制上更可疑（无真值，无法验证对错，但不应视为可信）。

**旁证**：初赛三代管线中的 GroundingDINO 一路本就是"三模态早期融合（5 通道 RGB+IR+Depth）"，数据集提供 `Images/infrared/` 与 `Images/depth/` 正是为此。故启用红外不是新增设计，而是补回被丢掉的一路输入。

### 10.2 处置（已实施）

范围**限定为 45 条无框条目**（用户决策），不动那 165 条有框的。

```
1) 上传 45 条所需的 44 张红外图（63 MB，实测 5.38 MB/s，耗时 0.2 min，失败 0）
2) `_retry_ir.py`：复用 `_locate_full.py` 的 load_model / infer_qid（判据不另写），
   只把输入源换成红外图，对 45 条重跑 LocateAnything-3B，落盘 bbox_all
3) `_watch_then_retry_ir.sh`：等 LA 全量结束后**自动**触发，含四道闸门
   （LA 产物完整性 / 红外图完整可读 / GPU 空闲 / 解释器依赖）
```

**重要性说明**：LA 全量跑的也是可见光图，对"热信号"这类问句同样会拒答——所以不能指望 LA 的可见光结果覆盖这 12 条，必须换模态。

## 13. 方法学备注（本项目反复出现、值得保留的教训）

1. **测量的判据必须先被测试**。`verify()` 对截断的探测能力、校验器对违规的识别能力，都是造出已知坏输入验证过的；否则"通过"不构成证据。
2. **口径错配会制造假结论**。核心词抽取的两段式实现曾分散在两个文件，导致 38 条结果漂移；现统一到 `_analyze_ordinal3.py`，并用初赛产物 SHA 逐字节回归验证。
3. **引用判据时要用对层次**。`valid_cand`（含 `MAX_AREA`）是"新框能否替换"的标准，误用于最终采纳会产出 null。
4. **长跑前的接线验证成本极低、收益极高**。冒烟测试与干跑回测共拦下 3 个会让 6–8 小时付之东流的缺陷（`bbox_all` 未落盘、`MAX_AREA` 误用、以及取框规则未定义）。
5. **不要用不可辨识的参数模型外推**。当拟合出现非物理系数（如"每图固定 −9.73s"）时，正确做法是承认模型不可辨识、改用有界估计，而非报告一个看起来精确的数。
6. **物理量探测要交叉验证**。`pgrep -f` 会匹配到承载它的命令行本身，造成"进程还在"的假阳性；须用 GPU 进程表或端口状态交叉确认。
7. **可视化绝不能引入系统性偏差**。为展示"多个版本框重合"，曾给不同版本加逐层外扩（0/6/12/18 px）绘制；结果零偏移的那版看起来最紧最准，直接导致"某版更好"的误判。**框必须一律按真实坐标绘制**；数值相同者应合并为一个框并标注共用的版本，而不是靠偏移去"区分"。凡是用于决策的图，都要按"读者会据此下结论"的标准来设计。
8. **看极端样本不能外推整体**。判定 v1/v2 优劣时，最初只看了 IoU 最小的 6 条（最极端差异），随即补了 IoU 中段的 8 条与随机 8 条两组对照。极端样本往往与典型样本成因不同，用它推整体不安全。
