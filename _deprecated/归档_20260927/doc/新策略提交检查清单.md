# 新策略提交标准化检查清单（M1–M6）

> **适用**：任何将消耗一次提交额度的新策略 / 新版本
> **依据**：`消融实验复盘.md` §4（功效判据）、§7（机制 M1–M6）
> **工具**：`_audit_ablation.py`（`--verify` / `--policy`）
> **三条铁律**：**先度量，后决定** ｜ **先写判读，后提交** ｜ **无结论就写无结论**

---

## 0. 使用方式

```
阶段 A 设计 ──→ 阶段 B 审计 ──→ 阶段 C 提交 ──→ 阶段 D 判读
（先度量后命名）  （硬约束+功效）   （登记+留痕）    （如实归档）
                      │
                      └── D < 36 → 停机，不消耗额度
```

**每阶段全部勾选通过，方可进入下一阶段。** 任一"一票否决项"（§5）不满足 → 不得提交。

---

## 1. 阶段 A：设计（M3 —— 先度量，后命名）

- [ ] **A1** 新策略的**具体判据改动**已写清（改了哪一条规则、触发条件是什么）
- [ ] **A2** 产物已生成，且**文件名不与既有策略冲突**（`result_qwen_<新名>.json/.zip`）
- [ ] **A3** 已确认它**不是**仅凭规则措辞差异就自称的"新维度"
      > 反例：`safe` 与 `shrink` 规则描述完全不同，实测只差 **17 条**；`qwen` 与 `full` 实测差 **0 条**
- [ ] **A4** 已跑 `python _audit_ablation.py --policy <新名>`，并记录：

      | 项 | 值 |
      |---|---|
      | 最近邻 | ______ |
      | 与最近邻的总差异 / **实质 D** / 微差 | ______ / ______ / ______ |
      | 预期可区分性 `0.335√D` | ______ σ |

- [ ] **A5** 若 D = 0 或"同物体、无实质差异" → **回到 A1 重新设计**，不要进入阶段 B

---

## 2. 阶段 B：审计（M1 + M2）

### B 组 1：硬约束（静态校验，一条命令）

- [ ] **B1** `python _audit_ablation.py --verify <新名>` **7 项全 ✓**：

      ```
      ✓ 条数 == 9555
      ✓ 键集 == test.json
      ✓ 字段集 == FIELDS
      ✓ bbox 有序且 ∈[0,1]
      ✓ 无 error 条目
      ✓ 冻结 6 条零改动
      ✓ zip 内 JSON == 磁盘
      ```

      并把输出的 **JSON SHA256** 记入 §7 模板

### B 组 2：运行一致性（两项机械检查）

- [ ] **B2** **双跑一致**：同一策略连跑两次 → JSON 与 ZIP **均逐字节一致**
      > `_fuse_qwen.py` 已固定条目时间戳（1980-01-01），故 ZIP 也应一致
- [ ] **B3** **既有产物零扰动**：提交前对全部既有产物做内容快照（内部 JSON SHA），重跑后比对 → **变动数 = 0**

### B 组 3：功效判定（M2 —— 先定类型，再定门槛）

- [ ] **B4** 判定**实验类型**。两类判据不同，**不可混谈**：

      | 类型 | 特征 | 要回答的问题 | 门槛 |
      |---|---|---|---|
      | **统计型** | 差异多、条目同质 | "这类改动整体是否有效" | 需 σ ≥ 2 |
      | **枚举型** | 差异 **≤ 20 条**且可逐条点名 | "这几条具体对不对" | **无门槛** |

      ☐ 统计型 → 走 B5　　☐ 枚举型 → 走 B5′

      > **依据（本项目实测）**：线上得分是**确定性**的，σ 描述的是"哪些条目会翻转"的未知，**不是测量噪声**。
      > 故差异集足够小时，结果直接给出**净值**，且可逐条还原对错——`merge`（0.6693）与 `merge_som`（0.6695）仅差 **2 条**，净值 +2 ⇒ **2/2 全对**，这是确定信息。

- [ ] **B5**（统计型）计算 `可区分性`（需含微差分量）：

      ```
      σ = (0.30·D_sub + 0.0028·n_mic) / √(0.80·D_sub + 0.0056·n_mic)
      ```
      - σ < 2 **且** 非"枚举型" → **停机**，标注"不产生知识"，**不消耗额度**
      - 纯实质差异的等价门槛：`D < 36`；纯微差的等价门槛：`n_mic < 2857`
- [ ] **B5′**（枚举型）**提交前**写死净值表：`D` 条 → 净值 ∈ {−D, −D+2, …, +D}，并写明每个净值读作什么
      > 局限：D 条只能定出**净值（赢数−输数）**，定不出赢数；故 D 不宜过大（≤20）
- [ ] **B6** 若判定"可测"（36 ≤ D < 200，或可测的微差型）→ 必须完成 **B7**；D ≥ 200 → 跳过 B7
- [ ] **B7** **判读档位已写定（提交前！）**，按下列三档填数：

      | 档 | 区间 | 判读含义 |
      |---|---|---|
      | 支持 | ≥ ______ | ______ |
      | **无结论** | ______ ~ ______ | **不得**读成"更优"或"不差" |
      | 反对 | ≤ ______ | ______ |

      > 档位必须**先于提交**写定。宽口径那次正是靠这一点，把 +3 条正确判成了"无结论"。

## 4. 阶段 D：提交后判读（如实归档，禁止事后附会）

- [ ] **D1** 按 **B7 写定的档位**判读 —— **不得改档、不得扩大解释**
- [ ] **D2** 若落"无结论"档 → 文档中**必须**写"无结论"，**不得**出现"更优""不差""可放心用"
- [ ] **D3** 回填 **"与前一版的实质差异"列**（M5）；更新 N 版对照表
      > 只有规则描述的消融表不合格：**名义相邻 ≠ 实际相邻**
- [ ] **D4** 记录 **预期 vs 实测**（若不符，**不得**只写实测而对预期避而不谈）
- [ ] **D5** 归档：zip 归入分数目录；同步交付说明 / 技术方案 / 记忆
- [ ] **D6** 若本次产生**新教训** → 追加到 §9 清单维护

## 5. 一票否决项（任一不满足即**不得提交**）

1. 容器硬约束 7 项有任一 ✗（B1）
2. 双跑不一致，或既有产物出现非预期变动（B2/B3）
3. `D < 36` 且目的不是补消融（B5）
4. `36 ≤ D < 200` 但**判读档位未在提交前写定**（B7）
5. 额度账本未登记（C1）
6. 无法用一句话说明"这次要回答什么问题"（C6）
7. 提交后判读与提交前档位不一致（D1，事后追溯同样适用）

## 6. 本清单的回溯验证（把最近 6 次提交代入）

| 候选 | D（实质） | 功效 | 清单判定 | 实际结果 | 清单是否有效 |
|---|---|---|---|---|---|
| 基线→`safe` | 1027 | 10.7σ | 应提交 | +363，明确为正 | ✅ 不误拦 |
| 窄 `qfb` | 281 | 5.6σ | 应提交（须写档位）| +82，明确为正 | ✅ 不误拦 |
| **`wide`** | **24** | **1.6σ** | **应停机** | +3，**判为"无结论"** | ✅ **拦得住** |
| `nosom` | 124 | 3.7σ | 应提交（须写档位）| +28，明确为正 | ✅ 不误拦 |
| **`shrink`** | **17** | **1.4σ** | **应停机** | +7（设计功效不足）| ✅ **拦得住** |
| `merge`（2 条人工焊接）| **2** | 0.5σ | **枚举型 → 应提交** | **+2 ⇒ 2/2 全对** | ✅ 且给出**确定**信息 |

**结论：本清单会拦下 2 次无效的统计型提交（`wide`、`shrink`），同时不误伤枚举型提交（最后一行）。**

> **最后一行的意义**：它正是 **B4 引入"实验类型"判定的依据**。若仍按最初的"σ<2 即不产生知识"一刀切，这次会被误拦——而它实际给出了全项目**唯一一次**"人工确认修正 2/2 全对"的确定性结论。

## 9. 清单维护规则

1. **每次产生新教训 → 必须新增一条可勾选项**（不是一句感想，必须能被机械检查或机械计算）
2. 新增项**必须写明"不通过怎么办"**（停机 / 重设计 / 记录备查）
3. **工具变更须回溯验证清单**：本次即为一例 —— `--verify` 首次运行时报出"zip 内 JSON == 磁盘 ✗"，实为大小写比较 bug（`hexdigest()` 小写 vs 大写），**是检查项自身的假阴性**。故新写/新改的检查项**必须先对已知良好的产物跑通，再做反向测试**（故意传错参数，确认会报错退出）
4. 清单的**阈值（36 / 200 / 2857 / 20 / 0.30 / 0.0028）随证据更新**；每次更新须注明依据与验证点数

### 已发生的修订（留痕）

| 日期 | 修订 | 触发原因 |
|---|---|---|
| 2026-09-19 | 功效判据由 `0.335√D`（仅实质差异）改为**两层模型**（实质 + 微差分别贡献期望与方差） | 只算实质差异会漏判"纯微差"对比：`qwen`↔`full` 实质差 0、微差 5486，实测 +15 条（2.8σ）确为可测，旧判据会误报"无差异" |
| 2026-09-19 | 工具输出由"预期净翻转 **+**N 条"改为"效应**幅度** ±N 条 + 方向提示" | 原写法**无条件假设新候选赚**；而微差层已测增益方向是【保留基线】，对反向候选（如 `qonly`）会给出**相反符号** |
| 2026-09-19 | M2 由"σ<2 一律停机"改为**先分实验类型**（统计型 / 枚举型） | `merge` 仅差 2 条、σ=0.5，按旧表述应停机；实际给出**净值 +2 ⇒ 2/2 全对**的确定信息。线上得分是确定性的，σ 反映的是"哪些条目翻转"的未知，**不是测量噪声** |

> **清单存在的理由**：本项目的两处浪费（`wide` D=24、`shrink` D=17）都不是判断失误，而是**零成本却未做的度量**。清单的作用就是把"本该做但没做"变成"不做就走不下去"。
