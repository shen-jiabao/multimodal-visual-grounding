> 参赛赛题：全球校园人工智能算法精英大赛 · 算法挑战赛 · 基于大模型的多模态视觉理解与推理
> 提交版本：`result_qwen_det_full_qfb_nosom`（9555 条）
> 线上成绩：**ACC@0.5 = 0.7827**
> 文档日期：2026-09-19

## 一、算法概述

本作品面向多模态视觉定位任务：给定可见光 RGB、红外、深度三模态图像与一条英文查询，输出目标在可见光图中的归一化边界框，评测指标 ACC@0.5，测试集 9555 条。

方案不做端到端训练，以开源大模型为主体、提示工程与规则融合为核心，三代迭代：GroundingDINO 三模态早期融合建立基线 → LocateAnything-3B 择优融合 → Qwen3-VL-8B-Instruct 全量定位并专设序数处理模块。最终线上 ACC@0.5 = 0.7827，较上一代基线（0.6695）提升 +0.1132。

创新有四。其一，针对序数查询的系统性失效（对不同序数输出同一框），提出 Set-of-Mark 三段法：枚举实例→叠加编号→询问编号→映射回框。其二，发现模型自报编号有系统方向偏差（从右到左错误率为左到右的 2.6 倍），改由查询文本推算期望下标，净成功率 39.6%。其三，以线上对照为唯一裁判，推翻"保留基线更安全"的假设，并实现得分可预测（预测 0.7708/实测 0.7709）。其四，再推翻"回退点只能放弃增益"：序数层保留基线的回退条目改由大模型直接框接管，实测累计 +0.0118（净增 113 条）。

## 二、实现方案

### 2.1 总体架构

![多模态视觉定位算法架构](技术方案_架构图.png)

整体架构为**多模型独立全量推理 → 按查询类型分流融合 → 硬约束校验 → 打包提交**。三代模型各自覆盖全量 9555 条查询，不依赖单一模型；融合层按查询类型选用不同证据源。全部推理均在本地／自建云端环境完成，未调用任何商业闭源大模型的在线接口。

### 2.2 解题思路

任务可分解为两个性质不同的子问题：

- **非序数查询**（7541 条，78.9%）：如"图中右侧的红色轿车"，考验单实例定位能力；
- **序数查询**（2014 条，21.1%）：如"从左数第三个石墩"，考验**多实例枚举与排序**能力。

实测表明两者失败模式完全不同：非序数查询是"定位精度"问题，序数查询是"**根本没有执行序数选择**"的功能性缺失。因此管线在融合层对两类查询分别处理：非序数直接采用大模型输出，序数则进入专门的 SoM／位置推算分支。

三代迭代的决策依据始终是**线上得分**而非内部指标，每一代都保留完整的候选版本与 SHA256 记录，可复现、可回退。

### 2.3 数据处理

#### 2.3.1 输入模态与规格（依据赛题数据说明）

| 模态 | 规格 | 处理方式 |
|---|---|---|
| 可见光 RGB | 三通道 8 位无符号整型，像素范围 [0,255] | 作为定位主模态；归一化后输入模型 |
| 红外 Infrared | **存储为三通道 8 位**（三个视觉特征高度一致的灰度图堆叠，无实际彩色语义），像素值越高表示温度越高 | 取单通道并做噪声抑制；仅用于第一代三模态融合 |
| 深度 Depth | **单通道 16 位无符号整型**，单位毫米，理论范围 [0,65535]，有效感知约 0.3–20 m；**像素值 0 或过小代表无效深度** | 离群值剔除与无效值（0）掩膜；仅用于第一代三模态融合 |
| 查询文本 | 英文句子，描述目标外观、空间位置或行为状态 | 直接作为提示词输入；序数查询额外做结构解析 |

#### 2.3.2 数据规模与解析

- 可见光图像 **2000 张**（1903 PNG + 97 JPG），测试查询 **9555 条**；一组图像组对应一个或多个查询文本。
- 按赛题要求正确解析 JSON：以查询文本 ID（如 `000000_001`）为索引关联三模态图像相对路径与查询文本，**不改动除 `bbox` 外的任何字段**。
- 混合格式处理：图像路径统一从 `queries.json` 读取，避免 PNG/JPG 扩展名硬编码导致的读图失败。

#### 2.3.3 序数查询结构解析

对 2014 条序数查询抽取「**方向词 + 序号 k + 核心名词**」三元组，规则迭代三版达到 0 失败：

- v1 → v2：由"整句截断"改为"取头名词短语"，解决 258 条过长、2 条为空的问题；
- v3：补充处理 `the Nth closest` 型（序数词出现在名词之后）句式。

同时建立**核心词可信度判据**：核心词按空格/连字符切词后，若所有词均落在修饰词集合（序数 + 空间词 + 冠词 + 泛义词 + 尺寸颜色形容词）内，即判定为"退化"，连同"序数词实为参照物"的情况一并列入**不可信集合**（实测 25 条），这些查询永不采用 SoM 结果。该判据刻意偏严：**假阳性只是放弃一次增益，假阴性则会主动引入错框**。

#### 2.3.4 坐标与输出规范

- 所有边界框归一化至 [0,1]，且严格保证 `x1 < x2`、`y1 < y2`；坐标越界值裁剪至合法区间。
- 面积超过图像 35% 的框视为"多目标合并框"予以拦截（硬约束）。
- 输出 JSON 保留 `visible` / `infrared` / `depth` / `query` / `bbox` 字段，仅写入 `bbox`。

### 2.4 算法设计与开发

#### 2.4.1 第一代：GroundingDINO 三模态早期融合（基线）

- 将 RGB(3) + 红外(1) + 深度(1) 拼接为 **5 通道输入**，改造 SwinT PatchEmbed 首层卷积 3→5 通道，复制预训练前 3 通道权重，实现早期融合。
- 检测参数：box 阈值 0.35、text 阈值 0.25；**候选池阈值单独降至 0.15**（边缘实例的 logit 常贴近 0.2，留出数值裕量）；NMS IoU 0.3 去重。
- 复杂属性查询采用**短语切分提示**；针对"人 + 前景物"纵向合并框，改用上位词（toy / animal / vehicle / furniture 等）换提示重新检测，以拆出独立实例。
- 空间语义后处理：按候选框空间关系（最近/最远、左/右）排序后取第 N 个，供序数查询使用。

#### 2.4.2 第二代：LocateAnything-3B 择优融合

- 模型配置：NVIDIA LocateAnything-3B，Parallel Box Decoding，慢速模式 + sdpa 注意力 + bfloat16，输出 0–1000 归一化 `<box>` 标签；隔离虚拟环境（Python 3.13 + transformers 4.57.1）。
- 38 条探针验证：命中率 92.1%，3.83 s/条；随后完成 2000 图全量推理，50 条/检查点支持断点续跑。
- **融合规则（"至少不变差"原则）**：
  - R0 无框 → 回退基线；R1 面积 >0.35 → 回退基线；
  - **R2 仅当 IoU < 0.2 且面积 > 1.5× 基线时才回滚**。核心判据是「**缩小是修正方向，放大才是漂移**」，该原则由 38 条真实探针标定（0 例"Locate 更优却应回滚"）；
  - 序数类保留基线（Locate 单框无法覆盖第 N 个实例）；结构类（护栏/围栏/栏杆）保留基线（单框欠覆盖长条结构）；区域类（湖面/水域等）豁免 R2。
- 4 个**护栏样本**（`000282_004`、`000282_008`、`002004_001`、`002004_002`）冻结，任何规则不得改动。

#### 2.4.3 第三代：Qwen3-VL-8B-Instruct + Set-of-Mark（最终提交）

**（1）直接定位**

Qwen3-VL-8B-Instruct 全量推理 9555 条，输出 JSON 格式 `bbox_2d`（0–1000 整数归一化）。实测有框率 99.2%，2.46 s/条，显存占用 17.5 GB，全量耗时 8.08 h。

**（2）序数层 SoM 三段法**（2014 条）

| 步骤 | 操作 |
|---|---|
| ① 枚举 | 以 `Detect ALL instances of "{核心词}"` 提示，获取该图全部同类实例的候选框，按 x 中心从左到右排序 |
| ② 标注 | 在图像上为每个候选叠加红色编号圆圈（1 = 最左，n = 最右）|
| ③ 选择 | 询问模型："图中标注了 n 个物体（1 = 最左，n = 最右），哪一个编号对应「{原查询}」？只回答编号" |
| ④ 映射 | 编号 → 候选框坐标 |

**（3）位置推算（det，关键改进）**

在 SoM 之上进一步**由查询文本程序化推算期望编号**，直接取 `cands[期望编号-1]`，不再依赖模型自报编号：LTR（从左到右）→ `k`；RTL（从右到左）→ `n_cands − k + 1`。

设置四个前提，任一不满足即**回落 SoM 模型编号分支**（不做主张）：① 候选表确实按 x 从左到右排列（容差 0.02）；② 方向明确；③ 序号可抽取且 ≤ 候选数；④ 序数词非方位介词引导的参照物。

**（4）融合层规则**

- **非序数（策略 `full`）**：与基线 IoU<0.5 时采纳 Qwen 框；IoU≥0.5（同一物体、仅框紧度不同）**保留基线**；Qwen 无有效框时保留基线兜底；
- **序数**：可推算则用 `det`（位置推算）；不可推算则用 SoM 模型编号；两条路径都不可用、或 SoM 被下列三类否决时，**改用 Qwen 直接框**；Qwen 亦无合法框时才回退基线；
- **SoM 被否决三类**：`SOM_UNTRUSTED`（核心词退化/参照物）、`SOM_UNDERCOVER`（k > n_cands，第 k 个实例不在候选表中，必然选错）、`SOM_FAIL_KEEP`（枚举失败）；
- **冻结集 6 条**（人工确认的 2 条 + 护栏 4 条）：任何策略不得覆盖。

### 2.5 模型训练与优化

#### 2.5.1 训练说明（如实声明）

**本方案未进行任何模型微调或训练**，全部使用公开预训练权重：GroundingDINO SwinT-OGC、LocateAnything-3B、Qwen3-VL-8B-Instruct。代码库中 `models/gd_lora.py`、`models/pose_classifier.py` 为前期设计的接口预留模块，**未产出训练权重，未参与最终管线**。

**未使用任何外部公开数据集**；数据增强亦未采用（本方案无训练环节）。全部数据仅使用赛事官方提供的测试集进行推理预测，未对测试集做任何标注、篡改或训练使用。

#### 2.6.3 线上对照实验（唯一真正的准确率证据）

| 提交版本 | 非序数口径 | 序数口径 | 线上 ACC@0.5 | 相对上一版 |
|---|---|---|---|---|
| `result_locate_merge_som`（第二代基线） | — | — | 0.6695 | — |
| `result_qwen_safe`（**补测**：保守） | 仅修基线明显错误（缺框/非法/面积>0.35） | SoM 模型编号 | 0.7075 | — |
| `result_qwen_shrink`（**补测**：保守） | 仅修基线宽合并框 | SoM 模型编号 | 0.7082 | — |
| `result_qwen_qwen` | Qwen 为准（合法即采纳） | SoM 模型编号 | 0.7590 | — |
| `result_qwen_full` | IoU<0.5 才换，一致时保留基线 | SoM 模型编号 | **0.7606** | **+0.0016** |
| `result_qwen_det_rb` | Qwen 为准 | 可疑条目回退基线 | 0.7613 | +0.0023 |
| `result_qwen_det` | Qwen 为准 | 位置推算 | **0.7692** | +0.0079 |
| `result_qwen_det_full`（上一版提交） | IoU<0.5 才换 | 位置推算 | **0.7709** | **+0.0017** |
| `result_qwen_det_full_qfb`（窄口径） | IoU<0.5 才换 | 位置推算 + 回退点改用大模型直接框 | **0.7795** | **+0.0086** |
| `result_qwen_det_full_qfb_wide`（宽口径） | IoU<0.5 才换 | 再 + SoM 一致条目改用直接框 | **0.7798** | **+0.0003** |
| **`result_qwen_det_full_qfb_nosom`（最终提交，最高）** | IoU<0.5 才换 | 再 + **弃用模型自报编号**，序数只认位置推算与大模型直接框 | **0.7827** | **+0.0029** |

> **两个保守策略补测（0.7075 / 0.7082）的额外价值**：它们**净成功率反而最高（35.3% / 35.4%，高于 `qwen` 的 31.1%）**，但只覆盖 1027 / 1044 条，总分远低；且两者**实质仅差 17 条**（同一策略的近邻）。由此"采纳量 → 得分"曲线有四点实测（`safe` 1039→0.7075 ｜ `shrink` 1158→0.7082 ｜ `full` 2769→0.7606 ｜ `qwen` 8255→0.7590），保守区几乎水平且低，**跳变在 1158→2769 之间**，而**采纳量最大者反低于中高者**——非单调再次被证实。**至此 10 个策略全部实测，消融实验穷尽。**

**两条可相加性恒等式**（两处改进落在**不相交**条目集上，故线性叠加）：

- 序数层：`(0.7613−0.7590) + (0.7692−0.7613) = 0.0102 = 0.7692−0.7590` ✓
- 跨层叠加：`det_full（预测） = 0.7590 + Δ非序数(full) + Δ序数(det) = 0.7590 + 0.0016 + 0.0102 = 0.7708` → **实测 0.7709，误差 0.0001 ≈ 1 条**

**加法模型经验证成立**（三条差值误差全在 1 条内）：`det_full−det` 预测 +0.0016 / 实测 +0.0017；`det_full−full` 预测 +0.0102 / 实测 +0.0103；`det_full−qwen` 预测 +0.0118 / 实测 +0.0119。这说明**当改动落在不相交的条目集上时，线上得分可事前预测**，本项目据此可在提交前对改进方案定档，而非仅事后解释。

**新发现（由 `full` 得分推出）**：`full` 相对 `qwen` 净增 15 条（+0.0016）。二者唯一的差别是 **5486 条"Qwen 与基线在同一物体上、仅框紧度不同（IoU≥0.5）"的条目**：`qwen` 采纳 Qwen 框，`full` 保留基线。结果保留基线略优。→ **在这批条目上，基线的框比 Qwen 的框更接近真值。**

**第三处改进（`det_full_qfb`，回退点改用大模型直接框）**：与 `det_full` 的差异 421 条**全部在序数层**（非序数层 0 处），281 条实质改动 → 净成功率 **29.2%**，线上 **+0.0086**。该结果同时**推翻了一个前期的判断**：这些回退点（SoM 枚举失败等）原被认为"只能放弃增益、保留基线"，实测说明改由大模型直接框接管反而净赚 82 条。

> **证据纪律**：本版**没有事前预测量**——与 `det_full`（预测 0.7708 / 实测 0.7709）不同，29.2% 的净成功率系**事后测出**，落在既有各版区间（10.8%–39.6%）内，属"与既有结论一致"而非"预测命中"。二者不可混为一谈。
>
> **第四处增量（宽口径）实测 +0.0003 → 判为"无结论"**：把 `SOM_AGREE`（基线与 SoM 一致）的 83 条也改由大模型直接框接管，线上 **0.7798**。该增量中与基线**实质不同仅 24 条**，净翻转 **+3 条**；点估净成功率 12.5% 低于窄口径的 29.2%，但在"每条改动 ±1"波动模型下仅偏离 **1.0–1.3σ**，**不构成结论**。
>
> **判读规则系提交前写定**：≥0.7805 支持"两来源共识可被单来源推翻"｜**0.7785–0.7805 判为"无结论、两口径不可区分"**｜<0.7785 支持"共识优于单来源"。实测 0.7798 落在**中间档**——故**不得**表述为"宽口径更优"，也**不得**表述为"宽口径不差、可放心用"。
>
> **第五处增量（弃用模型自报编号）实测 +0.0029 → 判读档位命中**：把 `SOM`（位置推算不可用、由模型自报编号决定）的 222 条改用大模型直接框，线上 **0.7827**，净翻转 **+28 条**（124 条实质改动 → 净成功率 22.6%，约 2.9σ，超出噪声）。判读规则（提交前写定）：≥0.7818 支持弃用｜0.7778–0.7818 无结论｜≤0.7778 支持保留 → **实测落第一档**。
> **结论：模型自报编号在最终数据里没有价值。** 与 `SOM_AGREE` 对照可互为印证——SoM 与基线**一致**时替换 ≈ 0（+3 条），**不一致**时替换 **+28 条**：**一致 = 框大概率已对；不一致 = 模型编号大概率是错的。**
> **须区分"选择"与"枚举"**：被否定的只是 SoM 的**选择**环节；候选表仍由 SoM 的**枚举**产生，位置推算那 1279 条完全依赖它，**SoM 机制整体仍有价值**。
> **方法论记录**：本条的事前点期望是 **≈0，这个判断是错的**；是"提交前划好档位"把 +0.0029 从"我以为的波动"里抢了出来（本项目第二次由事前写定纠正事后偏向）。

> 说明：赛题数据集不提供标注框，因此**本项目所有准确率证据均来自线上提交反馈**；内部指标仅用于一致性与合法性校验，不作为准确率依据。

## 三、算法创新点

### 创新点 1：面向序数查询的 Set-of-Mark 三段法（核心创新）

直接提示大模型定位序数目标是**系统性失效**的。实测显示：对"第一/二/三个石墩"三连查询，两个不同模型的独立输出给出**逐字节完全相同**的边界框——即模型完全未执行"取第 N 个实例"这一步。

本方案将其重构为可验证的三步：**枚举 → 编号 → 选择**，把序数选择从"模型的隐式推理"转化为"可检验的编号映射"。关键发现是**枚举提示词决定成败**：`Find every X` 仅返回 1 个框（SoM 直接失效），`Detect ALL instances of X` 可返回 5 个框。修复后，SoM 在已人工确认样本上独立复现了人工确认的窄框，**IoU = 1.000**。

### 创新点 2：序数位置的程序化推算（不信任模型自报编号）

在 SoM 基础上进一步量化发现：**模型自报编号与预期存在系统性方向偏差**——RTL（从右到左）查询错误率 27.6%，为 LTR 的 2.6 倍；其中 43.5% 的 RTL 错误表现为"忽略 1 = 最左的约定、直接按自身方向计数"。

据此改为**由查询文本自行推算期望下标**并直接取对应候选框，彻底绕开模型自报编号环节。该模块在 245 条实质改动上净增 97 条命中，净成功率 39.6%，高于全量平均的 31.1%。

### 创新点 3：以线上对照为唯一裁判，并推翻"基线安全"假设

项目前期长期遵循"未验证增益不动、保守保留基线"的原则。但线上对照显示：基线（0.6695）明显低于模型全量替换（0.7590），差距达 +0.0895，这推翻了前述倾向——

> **当"保守选项"自身也没有测量值时，保守并不等于安全，它只是把不确定性藏进一个未测的默认值。**

**该教训后来被两个保守策略补测精确化**（`safe` = 只在基线明显错误时才改，`shrink` = 只修基线宽合并框，线上 **0.7075 / 0.7082**）：它们的**净成功率反而最高（35.3% / 35.4%）**，输在**覆盖面太小**（1027 / 1044 条，约 `qwen` 的三分之一）。故更准确的表述是 —— **保守的代价不在准头，而在放弃覆盖面**：它把大量"本可改对"的条目留在了未测量的默认值上。另注：这两者**实质仅差 17 条**，属同一策略的近邻，故其两次对照的**信息增量≈0**。

该教训在项目后期**再次应验**：序数层中 429 个被判定"只能保留基线"的回退点（SoM 枚举失败等），实测改由大模型直接框接管后线上再增 **+0.0086**。**同一个错误被犯了两次，两次都是"把未测量的默认值当作安全锚"。**

此后所有融合决策均以线上对照为准，并保留 13 个版本（**11 个已提交、1 个未提交、1 个归档代际**）与完整 SHA256 记录，保证可复现与可回退。**另有一条纪律自本项目后期起建立：当候选方案的期望增益落在噪声内时，须在提交前写定判读区间**（见 §2.6.3），以免事后把任何结果都解释成支持原判。

### 创新点 4：证据分级与"至少不变差"的融合纪律

- **护栏样本冻结机制**：4 个已确认样本任何策略不得改动，作为跨版本回归守卫；
- **不对称回滚规则**：仅当"放大漂移"（IoU < 0.2 且面积 > 1.5× 基线）时才回滚，**缩小一律视为修正方向**——该原则由 38 条真实探针标定；
- **证据分级原则**：交付文档中严格区分"人工确认证据"与"未验证推断"（例如 253 条序数修正明确标注为"策略选定，非逐条目视核对"），避免未验证结论被后续误读为已验证。

## 四、问题与思考

### 4.1 序数盲区（最核心的困难）

**现象**：直接提示模型定位"第一个/第二个/第三个石墩"，两个独立模型均输出逐字节相同的框，表明模型未执行序数选择。

**解决过程**：设计 SoM 三段法（枚举 → 编号 → 选择 → 映射）。过程中发现**枚举提示词是隐性关键**：初版 `Find every X` 只得到 1 个候选，导致 SoM 完全失效；改为 `Detect ALL instances of X` 后获得 5 个候选，方案才真正成立。

**残留问题**：全量枚举失败率 18.5%（373/2014），且失败呈**组级聚簇**（同一图同一核心词的多条查询一起失败，因枚举每图仅执行一次）。瓶颈在**枚举**而非选择——候选充足时选择环节合法编号输出率达 98.9%。这些条目原先一律回退基线（被判定为"**放弃增益**"）；后续实测将其改由大模型直接框接管，线上净增 82 条——**"回退点只能放弃增益"这一判断本身是错的**。

### 4.2 序数编号与预期不一致

**现象**：模型自报编号与理论预期不一致（RTL 错误率 27.6%），且存在"倾向于答 1"的偏好。

**分析过程**：先做小样重跑实验试图验证——给模型算式它会复述算式，仅澄清"1 = 最左"的约定它又重复原答案。据此判定：**该实验无法验证正确性**（两种变体都是循环验证），且提示模型在很大程度上并未真正读取图上编号，而是从查询中的 k 直接推导答案。

**解决方案**：放弃依赖模型自报编号，改为**程序化推算期望下标**（方向词 + 序号 → 下标），仅在推算前提不满足时才回落模型编号分支。

### 4.3 工程与流程问题

| 问题 | 根因 | 解决方案 |
|---|---|---|
| 双进程争抢 GPU，吞吐减半（0.41→0.26 q/s）| 旧脚本未被真正终止（排查时按记忆中的脚本名检索进程，模式不匹配导致漏检）| 进程检查固化为硬判读（推理进程 >1 即告警），不再依赖记忆 |
| 模型下载完成判定永不触发 | 分片大小不均（第 4 片仅 2.7 GB），"每片 >3 GB"的判据失效 | 改为"无 `.incomplete` + 分片名齐全 + config 存在" |
| SSH 瞬态断连致自动化中断 | 网络抖动 | 捕获 SSH/OS 异常实现自动重连与重试 |
| 长任务中断需从头重跑 | 无断点机制 | 50 条/检查点，支持断点续跑 |
| 监控日志长时间不可观测 | PowerShell 管道缓冲 | 改为脚本自行落盘并强制 flush |

### 4.4 认知层面的教训（本项目最有价值的两条）

**教训一：格式成功率 ≠ 准确率。** 项目曾两次把"输出格式解析成功率"误当作准确率依据（例如"38/38 命中"实际只是格式成功）。此后明确界定各指标含义：`iou_vs_merge` 衡量的是与基线的**一致度**、位置推算自洽率衡量的是**自洽性**——**三者均不衡量正确性**。

**教训二：不要给未经验证的选项以"安全"特权。** 详见创新点 3。可推广为一条工作规则：**面对"保留现状 vs 采用未验证改动"的抉择，先问——现状本身有测量值吗？**

### 4.5 不足之处分析

| 不足 | 具体表现 | 影响与说明 |
|---|---|---|
| **序数枚举能力受限** | 枚举失败率 18.5%（373/2014 条）；该类条目现已改由大模型直接框接管（实测净正 +0.0086），但**枚举不足本身造成的损失仍未消除** | 瓶颈已定位在枚举而非选择（选择环节合法编号率 98.9%）；进一步提升需更换更强的枚举提示词或重训检测头，本轮未做 |
| **多目标查询只取首框** | 约 63–73 条以数量词开头的查询（Two / Three / the row of …，条数随口径浮动）需覆盖多个实例，现管线只取首个框；其中**模型确实返回多框的仅 6 条**（2026-09-19 独立复核），其余为模型自行合并。已定位样本 `000002_002`"两把白伞" | 属明确的功能缺口，但**收益上限仅 +0.0006 分**（6 ÷ 9555）；根因是输出解析只取首框，且全量仅存 `raw[:200]` 已截断，事后无法可靠恢复 |
| **无框条目被迫回退** | 非序数 227 条大模型未给出合法框；序数另有 7 条（大模型亦无有效框）只能保留基线 | 理论可提升空间约 **+0.0238 分**（227 ÷ 9555）|
| **位置推算依赖候选排序质量** | 多候选记录中严重逆序 213 条，只能排除而不能修正 | 推算集内仍有 33 条属轻微逆序（容差 0.02 内）|
| **多模态协同未充分利用** | 最终两代模型仅使用可见光 RGB，红外与深度仅参与第一代融合 | 与赛题"多模态协同"的期望存在差距；红外/深度的互补价值在最终版中未体现 |
| **鲁棒性未做系统验证** | 赛题要求考察单模态质量退化下的稳定性，本项目未做模态质量退化的系统实验 | 只能说明机制层面具备一定容错（枚举失败、无框均有回退路径），但**无实验证据** |
| **得分不可分解** | 线上仅返回整体 ACC@0.5，无逐条反馈 | 无法定位未达标条目的具体分布；数据集无标注框，本地无法自建评测 |
