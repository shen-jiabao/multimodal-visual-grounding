# 消融实验完整复盘

> 对象：本项目基于 Qwen3-VL 的规则融合策略消融（11 个版本，全部经线上实测）
> 日期：2026-09-19 ｜ 状态：**消融已穷尽**（10 个策略全部实测）
> 重点：**策略重叠的发现**，以及由此建立的**提交前预防机制**

## 0. 摘要（五条结论）

1. **名义 11 个版本，实际只有 5 个独立策略家族**（簇内实质差异 ≤185 条，簇间 ≥203 条）。**10 次策略提交中有 6 次，其最近邻此前已测过**（即在同家族内重复）——只有 4 次真正开出了新家族。
2. **差异分两层，杠杆差 100 倍**：实质差异（换了不同物体）净成功率约 **30%**；微差（同物体、仅框紧度不同）实测 **≈0.28%**。两次干净测量一致。
3. **得到一条可用的提交前功效判据**：`可区分性 ≈ 0.335 × √D`（D = 与最近已测版本的**实质**差异条数）。**D < 36 条时，该次提交不产生知识**。该公式在 6 个实测点上成立，并**正确预言了唯一一次"无结论"**。
4. **根因**：我用**规则条件的语义**去划分策略空间，而没有用**输出的实际差异**去度量它。语义上"四个不同口径"，输出上只有"两个家族"。
5. **代价与收益**：至少 1 次提交额度的边际信息 ≈ 0（`safe` / `shrink` 只差 17 条）。但两轮补测仍产出了第 2 条结论（微差与实质差异的杠杆分离）。**若提前做两两差异矩阵（一条命令、数秒），可省下一次额度。**

> 这一条本身就是本次复盘要建立的纪律：**只在能干净分离自变量时才计算效率**。

## 4. 发现三：一条可用的提交前功效判据

### 4.1 推导

设某候选与**最近已测版本**的实质差异为 `D` 条，每条翻转 ±1，则

```
预期净翻转 ≈ 0.30 × D                 （0.30 取实测中位数）
噪声 σ     ≈ √(0.8 × D)               （P(增益)+P(损失) 约 0.8）
可区分性   = 0.30D / √(0.8D) = 0.335 × √D
```

**判定：`0.335√D < 2`（即 D < 36）时，该次提交落在噪声内，不产生知识。**

### 4.2 在 6 个实测点上验证

| 对比 | D | 预期可区分性 | 实测结果 | 判据是否正确 |
|---|---|---|---|---|
| 基线 → `qwen` | 2769 | 17.6σ | +855（明确为正）| ✅ |
| 基线 → `safe` | 1027 | 10.7σ | +363（明确为正）| ✅ |
| `det_full` → 窄 `qfb` | 281 | 5.6σ | +82（明确为正）| ✅ |
| `qwen` → `det` | 245 | 5.2σ | +97（明确为正）| ✅ |
| `wide` → `nosom` | 124 | 3.7σ | +28（明确为正）| ✅ |
| **窄 `qfb` → `wide`** | **24** | **1.6σ** | **+3（判为"无结论"）** | ✅ **正确预言** |

**判据唯一一次给出的"不可区分"预言，与实测结果吻合。** 这是它可用的最强证据。

### 4.3 用法

在**提交前**算一次，取代主观臆断：

```
D ≥ 200   → 强实验（可测出明确正负）
36 ≤ D < 200 → 可测，但需按 §4.1 写定判读档位
D < 36    → ★ 不产生知识：不要消耗额度（除非目的是"消融完整性"或见 §4.4）
```

### 4.4 两类实验不可混谈（对 §4.3 的重要限定）

§4.1 的 σ 是**统计型**实验的判据——它回答的是"**这一类改动整体是否有效**"。但本项目还有另一类实验，判据完全不同：

| 类型 | 特征 | 要回答的问题 | 门槛 | 结果形态 |
|---|---|---|---|---|
| **统计型** | 差异多、条目同质 | "这类改动整体是否有效" | 需 σ ≥ 2 | 是/否 + 置信度 |
| **枚举型** | 差异**极少且可逐条点名** | "这几条具体对不对" | **无门槛** | **净值整数**，可逐条还原对错 |

**关键区别**：线上得分是**确定性**的——同一个提交必然得同一个分，没有抽样噪声。§4.1 里的 σ 描述的是"**哪些条目会翻转**"的未知，**不是测量噪声**。因此差异集足够小时，结果直接给出

```
净值 = 赢数 − 输数          （D 条改动 → 净值 ∈ {−D, −D+2, …, +D}）
```

**本项目的一个实测范例**：`result_locate_merge`（**0.6693**）与 `result_locate_merge_som`（**0.6695**，基线）**只差 2 条**——正是两条人工看图确认的 SoM 焊接（`000023_001`、`000023_005`）。净值 **+2** ⇒ **两条**全部改对。

- 若按 §4.1 的 σ 判据（D=2 → σ≈0.5）会误判为"不产生知识"而拒绝提交
- 而它实际给出的是**全项目唯一一次**"人工确认修正 2/2 全对"的确定性结论
- 局限：D 条只能定出**净值**，定不出赢数；故 D 不宜过大

> 这一条修正了本文档 §4.3 的最初写法，依据见 `新策略提交检查清单.md` §9「已发生的修订」。

## 5. 根因分析：我具体错在哪

### 5.1 错误一（根本）：用「规则语义」代替「输出度量」来划分策略空间

四个非序数口径（`safe` / `shrink` / `full` / `qwen`）在**定义上**层层递进，看起来是"一个维度上的四个点"。但实测：

- `safe` 与 `shrink` **只差 17 条**（同一家族）
- `qwen` 与 `full` **实质差 0 条**（同一家族）

即：**"语义上的四个口径"实际只有两个家族，"语义上的两层"实际只是一层。**

> 规则措辞的差异 ≠ 输出的差异。策略空间的维度必须由**度量**建立，不能由**命名**建立。

### 5.2 错误二：上一轮我用「改动量接近」当作判断依据

实测前的原话大意是"`shrink` 的改动量（1158）紧邻 `safe`（1039），先验很弱"。
**方向侥幸对了，依据是错的**——`1158` 与 `1039` 是各自相对**基线**的改动量，两者的接近**不能推出**彼此接近。真正的依据是它们的**直接差异 = 17 条**，而我当时没算。

> 正确表述应是："`shrink` 与 `safe` 的**直接实质差异仅 17 条**（待测）"——而这需要一次测量，成本几秒。

### 5.3 错误三：从未在提交前计算候选间距离

后处理是**纯 CPU、秒级、可双跑复现**的。整张两两差异矩阵（11 个版本、55 对）在本次复盘中**一次命令算完**。此前 11 次提交中，**一次都没算过**。

> 这是"零成本却未做"的典型：不是没有手段，是没有把它列为**提交前的必经步骤**。

### 5.4 设计缺陷：消融计划缺少「正交化」环节

原计划的消融是"沿着我认为的维度逐点扫"。正确做法应有两步：

1. **先枚举全部候选 → 算两两差异矩阵**（零成本）
2. **按差异聚类，再决定"哪些点真正值得提交"**（同家族只保留代表）

缺少第 1 步，导致把 2 个候选当成 2 个独立实验。

## 6. 代价核算

| 项 | 数值 |
|---|---|
| 10 次策略提交中，**最近邻此前已测过**（同家族内重复）的 | **6 次**（`full`、`det`、`det_full`、`wide`、`nosom`、`shrink`）|
| 其中边际信息 ≈ 0 的 | **≥1 次**（`safe` → `shrink`：D=17，**设计功效仅 1.4σ**，观测 +7 条 ≈1.9σ，不足以可靠检出）|

| 实际收获 | ① 覆盖-准头分离（保守输在覆盖面）② 微差杠杆 ≈0.28%（第 3 条结论）③ **本条复盘本身** |

> 结论：成本不是"错"，而是**本可零成本避免的重复**。

## 7. 预防机制（已可直接执行）

> **配套操作清单**：`新策略提交检查清单.md` —— 把 M1–M6 展开为 A 设计 / B 审计 / C 提交 / D 判读 四阶段的逐项可勾选清单，含一票否决项、命令速查与记录模板。
> 本节说明每个机制的**理由**；清单说明**怎么照做**。

### M1 —— 提交前强制「差异矩阵」（机械步骤）

任何新候选，**提交前**必须跑：

```powershell
python _fuse_qwen.py --policies <新策略>        # 先产出
# 再算它与全部已测版本的实质差异（见 §8 脚本）
```

输出必须包含：与**最近邻**的 `总差异 / 实质 / 微差`，以及最近邻的名字。

### M2 —— 功效判据（硬门槛）

用 §4.1 的 `0.335√D` 判定：

- `D < 36` → **不提交**（标注"不产生知识"），除非明确目的是补消融完整性
- `36 ≤ D < 200` → 可提交，但**必须**在提交前写定判读档位（沿用宽口径那次的做法）
- `D ≥ 200` → 正常提交

### M3 —— 策略设计「先度量、后命名」

新增策略时，禁止仅凭"规则条件的语义差异"就认定它是新维度。**先产出产物、算与其他策略的差异**，再决定它是否值得进入消融表。命名应反映**实测差异**，而非规则措辞。

### M4 —— 额度账本

每次提交前登记一行：`候选 | 目的（追分/关未知/补消融）| 最近邻及 D | 预期可区分性 | 判读档位`。
目的为"补消融"且 `D<36` 的，**排队到最后**。

### M5 —— 消融表必须带「差异列」（文档纪律）

策略对照表除"规则差异"外，**必须**列出"与前一版本的实质差异条数"。只有规则描述的消融表，会让人误以为相邻版本是等距的（本次 `safe`/`shrink` 相邻但差 17 条，`qwen`/`full` 相邻但差 0 条，而 `full`/`det` 相邻却差 245 条——**名义相邻 ≠ 实际相邻**）。

### M6 —— 同家族只留代表

同一家族的多个成员，**默认只提交分数最高的一个**；其余仅在下列情况才花额度：① `D ≥ 36` 且能回答一个明确问题；② 需要消融的完整性。

### 提交前 Checklist（可直接照做）

```
[ ] 新候选已产出，且双跑 JSON/ZIP 一致
[ ] 已算与全部已测版本的实质差异矩阵，已知最近邻与 D
[ ] D ≥ 36（否则标"不产生知识"，不消耗额度）
[ ] 若 36 ≤ D < 200：判读档位已写定（提交前！）
[ ] 额度账本已登记本行（目的 / 最近邻 / D / 预期可区分性）
[ ] 消融文档已补"与前一版的实质差异"列
```

### 8.2 判据实现要点（已落在 `_audit_ablation.py` 中）

```python
# 实质差异：IoU < 0.5 且数值不同；微差：数值不同但 IoU >= 0.5
tot = sum(1 for q in A if norm(A[q]) != norm(B[q]))
sub = sum(1 for q in A if norm(A[q]) != norm(B[q]) and iou(A[q], B[q]) < 0.5)

# 功效判据
power = 0.335 * sub ** 0.5          # < 2 → 不产生知识（D < 36）
```
