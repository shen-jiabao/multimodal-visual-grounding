现场演示材料（答辩用）
======================

用途：让评委在**现场**看到"结果文件是本队自己做的"——不是翻 PPT，而是当场跑、当场看日志、
当场比对指纹。本目录把现场要用的脚本、命令与**核心代码**都备好，避免现场手忙脚乱。

一、三个方案（建议 ②→① 连做，7 分钟）
--------------------------------------

  方案① 本地离线核验（最稳｜零网络｜约 3 分钟）
        脚本：demo_local_verify.ps1
        命令：powershell -ExecutionPolicy Bypass -File 现场演示\demo_local_verify.ps1
        看点：① 包级自检「指纹 14/14 · 硬约束 4/4 · 改动面 519」
              ② 结果件四项硬约束全过
              ③ 装配器 8 组夹具 / 20 项断言全过
              ④★ 离线**逐条重建**交付件（六桶 329/100/3639/519，与提交件逐条一致）
        ⇒ 这一条**最有说服力**，且完全不受会场网络影响。

  方案② 服务器只读取证（约 4 分钟｜需网络）
        脚本：demo_server_evidence.sh（上传到服务器后 bash 执行；内容也可整段粘贴）
        命令：ssh -p 43504 root@connect.westd.seetacloud.com     # 密码当场手动输入，勿投屏
              cd /root/rivermind-data && bash demo_server_evidence.sh
        看点：① 上游产物的**纳秒级**时间戳  ② 权重 18 片「大小+sha256」双验的显式终态
              ③ 起服自证 `id=qwen38-27b`    ④ vLLM 真实跑过的参数与显存读数
              ⑤ 权重/数据/词表指纹与包内**逐位一致**
              ⑥ 互动：请评委任点文件，当场 stat + sha256sum 与包内清单比对

  方案③ 现场跑一次真推理（可选｜需提前准备｜起服 3–5 分钟）
        前提：在 AutoDL 控制台把实例切回**有卡模式**（重启后 SSH 端口/密码可能变，须提前一天确认）
        命令：bash /root/rivermind-data/_get_serve_q38.sh        # 就绪自证（约 110 秒）
              curl -s localhost:8000/v1/models | head -c 200     # 现场回读模型 id
              python /root/rivermind-data/_q38_gate.py --n 20    # 20 条冒烟闸门
        风险：起服占 51 GB 显存、编译期 1–2 分钟；若超时**立即切回方案①/②**。

  ⚠ 服务器现状（2026-10-15 实测）：实例处于**无卡模式**——`nvidia-smi` 为 0 字节占位且
    `Permission denied`、无 `/dev/nvidia*`、vLLM 未运行、8000 端口未监听。
    ⇒ 现在**只能演"证据"、不能演"推理"**；要走方案③必须先切有卡。
    （数据与代码都在：`models/Qwen3.8-27B` 31 项、磁盘可用 43 G、外网出口正常）

二、本目录文件
--------------

  README.txt                 本文件

  demo_server_evidence.sh    方案②：服务器只读取证一键脚本（仅 stat/head/tail/grep/sha256sum/ls/du）
  核心代码摘录.md            ★ **核心代码**逐字原文（判据 / 装配器 / 校验器 / 提示词与请求 / 起服脚本），
                             每段标注文件与行号，现场可随讲随翻
  核心代码文件清单_SHA256.txt 上述源文件的 SHA256（可当场 sha256sum 比对）

三、核心代码怎么用（现场话术）
------------------------------

  打开 `核心代码摘录.md`，按 A→E 讲五件事：

    A `code/_fuse_qwen.py`       判据的**唯一实现**（几何护栏 + 序数规则原语）；
                                 装配器/校验器/可视化器一律 import 它 —— 判据不会两处漂移
    B `code/_assembly_32b.py`    六桶**互斥**分类 + 总和断言 + 「序数层逐位不变」硬断言
                                 ⇒ "单变量"是可判定的约束，不是口头承诺
    C `code/_validate_semi.py`   刻意**不复用**融合器的内存对象，直接读要提交的 zip
                                 ⇒ "自己校自己不算校验"
    D `code/_qwen_full_pipeline.py` 三套提示词逐字原文 + `RE_BBOX` 唯一实现 + `temperature=0.0`、
                                 `JPEG quality=95`、base64 data URI 的请求构造
                                 ⇒ 换模型时**提示词一字不改**（所以得分差可归因到模型）
    E `code/remote_shell/_get_serve_q38.sh`  权重不完整**拒启**、就绪以 HTTP 为准、起服后回读自证

  现场可执行的最小自证三条（`核心代码摘录.md` §F）：
    ① 判据只有一处        ② 单变量是硬断言        ③ 校验器独立于融合器

四、建议分镜（7 分钟）

  4:00–6:30  **方案②**（服务器）：六条取证命令，边跑边讲

五、防翻车清单
--------------

  1. 网络：会场常封高位端口 ⇒ 备 4G/5G 热点；**提前一天用同一网络试连一次**。
  2. 端口/密码会变：实例重启后 `connect.westd.seetacloud.com` 的端口与密码可能变，
     当天早上再确认。
  3. **不要投屏密码**：全程手动输入；或提前配好 `~/.ssh/config` 用密钥登录；
     清理终端历史回显（演示前 `history -c` 或另开干净终端）。
  4. 终端观感：字号 16–18 pt、深色主题；方案②的脚本可整段粘贴，避免现场手打出错。
  5. 兜底：断网时直接翻 PPT 的 6 张证据附图（`代码与数据/远端现场证据/服务器取证/附图/`），
     它们与随包日志逐字一致。
  6. 若做方案③：**先跑通一次再上台**；并准备好"超时就切回方案①/②"的话术。
