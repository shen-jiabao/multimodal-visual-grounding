## 三、全流程总览

赛事数据含初赛 / 复赛 / 半决赛评测集，本项目实际使用其中两套：

```flow
[1] 初赛评测集（9555 条）：建立可用基线并逐版迭代 → 0.6693 → … → 0.7827
[2] 复赛评测集（5690 条查询 / 1295 图）：分层攻 → 0.7459 → … → 0.7963（★交付件）
[3] 数据格式勘查：发现"两个格式子群"（赛题文档只写了一个）
[4] 序数层（1103 条）：改为确定性规则（净 +79）
[5] 非序数层（4587 条）：逐级单变量换更强定位模型（净 +194）
[6] 出件：六桶互斥装配 + 硬约束校验 → result_semi_q38_nonord.zip
```

**贯穿全流程的两条自研方法论**（这是本项目最有分量的产出，也是"自主性"的直接体现）：

1. **无真值下的确定性读数**：赛题不提供 `test.json`（无任何真值）⇒ 本队发明**归零法**——
   交一件把某子集框换成"必然错的角落小框（面积 ≤1e-4）"的**测量件**，平台按**历史最高分**记录
   （测量件不拉低成绩），返回的得分数值**直接读出**其余子集的真实正确条数。
   读数口径是**恒等式**：`得分 × 5690 = 非序数正确数 + 序数正确数`，`1 条 = 0.000176`。
2. **判据预登记 + 单变量隔离**：每条杠杆的作用域 / 闸门 / 事前预期 / 止损线**先写进预登记文件再跑**，
   且每件只改一层、其余层**逐位不动**（**硬断言**，不是"构造上应该不动"）⇒ 得分差可干净归因。

### STEP 1　赛事数据接入与键集确认

* **目的**：正确解析赛事 JSON，按 Query ID 关联三模态图像与文本查询；确认提交键集。

* **输入**：官方 `queries/queries.json`（1,279,352 字节，5690 条）。

* **产物/结论**：`queries.json` 的 SHA256 = `717d15a1b9c270befa3b5930d0b9b00ef9c567c91bd0d54819ef0e17de5795c4`；
  被引用可见光图 **1295 张**（缺失 0、损坏 0）。

* **说明**：复赛**未提供** **`test.json`**，本队不凭"应与初赛同构"的假设，而是用初赛提交件实测确认

### STEP 2　数据格式勘查（发现赛题文档未记载的事实）

* **目的**：避免因格式假设错误而整批丢分。

* **发现**：被引用 1295 张图**分两个格式子群**，赛题文档只描述了其中之一：

  | 子群               | 张数           | 分辨率         | 深度存储                                                      | 红外                   |
  | ---------------- | ------------ | ----------- | --------------------------------------------------------- | -------------------- |
  | `.png` 组         | **1198**     | 1920×1080   | `I;16` 单通道 uint16、单位毫米、实测 0–19999                         | PNG，三通道近似相同（\|Δ\|≤1） |
  | **`.jpg`** **组** | **97（7.5%）** | **640×360** | **`RGB`** **三通道且逐像素相同** ⇒ 实为 **8 位灰度**；JPEG 有损、16 位量程不可还原 | JPEG，三通道完全相同         |

* **工程陷阱**：把 3 维数组直接交给 `Image.fromarray(arr, mode="L")` 会抛
  `ValueError: Too many dimensions: 3 > 2`，**使那 97 张（7.5%）整批失败**。

* **处置**：对 `.jpg` 组**直通原值、不按未知比例缩放**（赛题语义只需"越亮越远"的单调性）；
  零回归验证：`.png` 组新实现与旧规则输出**逐位相同**。

* **落点**：`code/_qwen_full_pipeline.py` 的 `load_depth()`；分析脚本 `code/_survey_modality_semi.py`。

### STEP 3　查询分层：序数 / 非序数（作用域由此确定）

* **目的**：把"模型擅长的"与"模型不擅长的"分开，为分层施策提供作用域。

* **命令/产物**：

  ```bash
  python code/_analyze_ordinal3.py --dataset "复赛数据集-基于大模型的多模态视觉理解与推理" --out _rebuild_cores.json
  ```

  产物 `_rebuild_cores.json` 应与随包 `_ordinal_cores_r2.json`（SHA256 `CFBA587D75AE3FB53CD64BFCC5E684EB81369C6B67AEA022F4D7B945DAEB80C2`）**逐条相同**。

* **结论**：**序数层 1103 条**（19.4%，如"从右数第二个"）＋ **非序数层 4587 条**。
  序数层核心准确率仅 **61.2%**（归零法实测，错 428 条），是全场最弱层。

* **产物/指纹**：随包 `_semi_qwen3vl_all.json`、`_semi_qwen3vl_som_all.json`、`_semi_retry_*.json`。

* **线上**：**0.7459**（`result_final_semi`，SHA256 `1A9E4FCD98531470C2EC3D1484D0CA9FF66781BD0390D7984E3F7AC314E69C73`）。

### STEP 5　补框链：覆盖率优先（零空框）

* **动机**：模型对约 7%\~9% 的条目输出空数组（认为图中无该物体）。**留空必然错，基线框至少还有猜中的机会。**

* **落点**：`code/_fuse_semi.py --fill-full`；后续由装配器「桶 1：无框 → 保留基线」制度化。

### STEP 6　序数层确定性规则链（L2，净 +79）【纯 CPU】

* **目的**：序数指代交给**查询文本程序化推算**，而不是交给模型猜。

* **命令**：

  ```bash
  python code/_variant_det_semi.py --which det --selfsort --qfb --yaxis
  python code/_enum_merge.py --trunc --zip-trunc --base result_semi_ord_det_ss_y_qfb
  ```

* **五层（各层改动集互不相交）**：

  | 层          | 含义                               | 改动面 → 净翻转     |
  | ---------- | -------------------------------- | ------------- |
  | `det`      | 水平轴**文本推算**（从查询里的序数词推"第 k 个"该在哪） | 136 → **+53** |
  | `selfsort` | 候选**自排序**（枚举候选按位置重排后再取第 k 个）     | 41 → **+9**   |
  | `qfb`      | **回退点改用直接框**（推算失败时不再用 SoM 选号）    | 47 → **+3**   |
  | `yaxis`    | **垂直轴**序数（上下方向的"第 k 个"）          | 10 → **+3**   |
  | `trunc`    | **枚举截断组修复**（枚举召回不足者换提示词重跑并合并）    | 52 → **+11**  |

* **线上**：0.7552 → 0.7568 → 0.7573 → 0.7578 → **0.7598**（`result_semi_enum_trunc`，SHA256 `07E2827CFFC132279E4CD72AA4E95067EA7000FF84508BC57FB6A467379BAD86`）。

* **校验（外部交叉验证）**：序数层 596 → **675**（净 +79），与五层之和 `53+9+3+3+11 = 79` **逐条吻合**。

### STEP 7　强制停损：判定并关闭"跨机制"路线

* 本队对每条新路线都先写预登记再跑，并在实测为负时**封口**（不留模糊）：
  序数层 32B SoM **0.7729**（66 改动 → 净 **−7**，约 6σ）⇒ 触发止损；
  深度序数轴 **0.7592**（净 −3）；GD 候选池 **0.7566**（净 −18.6%）；8B 提示合并 **0.7541**（净 −24.8%）；
  VLX-Seek **0.7492**（净 −156）。

* **结论（本队自研的机制判据）**：「**可迁移的不是规则文本，而是被替换那一层的性质**」——
  跨机制替换在本项目 **5/5 全负**，同机制（direct 框换 direct 框）四次全正。

### STEP 8　非序数层 L3：32B-AWQ 重跑 4587 条【GPU】

* **目的**：**同机制模型升级**（8B direct → 32B direct），只改非序数层。

* **输入**：`QuantTrio/Qwen3-VL-32B-Instruct-AWQ`（19.12 GB / 7 分片），vLLM 0.11.0（AWQ/awq\_marlin，TP=1）。

### STEP 10　非序数层 L5：32B **bf16** 精度修复【GPU】
