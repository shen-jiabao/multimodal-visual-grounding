交付包自检
==========

本目录用于**一次性复核本交付包的全部关键主张**（只读、纯 CPU、仅标准库）。

一、`_verify_package.py` —— 自动自检（推荐先跑这个）
---------------------------------------------------
  cd AIC-2026-14375345-代码与数据/自检
  python _verify_package.py

  它做三件事：
    [1] 关键文件指纹 14 项：交付件 / 装配输入 / 序数词表 / 查询索引 / 环境实录 /
        技术报告 PDF / 权重清单 / 判据预登记 / 冻结稿 / 远端原件主管线 /
        运维脚本归档起服脚本 / 闸门 G2 产物 / 改动面拼版 / 装配底座
        ——逐一比对 SHA256；
    [2] 交付件硬约束 4 项：条数 5690 / 键集与 queries 一致 / 四字段原样回显 / bbox 全合法；
    [3] 改动面读数：交付件相对 0.7786 基线的真分歧条数应为 **519**（判据 IoU < 0.5）。

  **预期输出**（末行）：
    结论：✓ 全部通过（指纹 14/14、硬约束 4/4、改动面 519）

  退出码：0 = 全过；1 = 有失败（逐条打印失败原因）。

二、`包内文件清单_SHA256.txt` —— 全包指纹台账
---------------------------------------------
  列出本包**每一个文件**的相对路径、字节数与 SHA256（不含本清单自身），
  供评审**整体校验**"包有没有被改动过"。校验方法（Windows）：

    Get-ChildItem -Recurse -File | ForEach-Object {
      $h=(Get-FileHash $_.FullName -Algorithm SHA256).Hash
      "{0}  {1}" -f $h, $_.FullName } > 实际.txt
    # 与 包内文件清单_SHA256.txt 比对

  或直接跑 `_verify_package.py`（它已覆盖全部关键文件）。

三、与其它自检脚本的关系
------------------------
  本目录脚本负责"**包级完整性**"（指纹 + 读数和）；
  其它自检脚本负责"**算法级正确性**"，位置与用途如下：

    code/_validate_semi.py    结果件四项硬约束（与 [2] 同源，独立实现）
    code/_test_assembly.py    装配器 8 组夹具 / 20 项断言
    code/_assembly_32b.py     ★离线逐条复算交付件（见 复赛流程.md §4.4）

  完整复现/核验流程见包根 `比赛流程与自证材料.md` §6 与
  `全流程逐步实录_模型与提示词.md` §6。
