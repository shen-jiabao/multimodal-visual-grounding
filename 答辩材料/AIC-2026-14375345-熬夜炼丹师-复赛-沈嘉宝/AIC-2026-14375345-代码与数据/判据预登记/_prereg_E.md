## 3. 输出适配（★已研究，结论如下）

### 3.1 坐标约定**相同**——不需要换算

InternVL 官方文档（`internvl.readthedocs.io` 的 Chat Data Format）：

> For grounding or detection data, we normalize each coordinate box to the range
> **[0, 1000]** using the width and height of the image, and round the normalized
> coordinates to integers.

⇒ 与 Qwen 的约定**一致**（0–1000 整数归一化）。**几何判据（`_fuse_qwen` 的
`norm/order/area/iou/usable`）一字不改。**

### 3.2 差别只在"JSON 包装"与"提示词句式"

| | Qwen（现行） | InternVL3.x |
|---|---|---|
| 输出 | `[{"bbox_2d": [x1,y1,x2,y2], "label": "object"}]` | `[[x1,y1,x2,y2]]`（**裸数组**） |
| 坐标 | 0–1000 整数 | **0–1000 整数（相同）** |
| 提示词 | `Locate the object described below…` | 接地句式：`Please provide the bounding box coordinate of the region this sentence describes: <ref>{q}</ref>` |

依据：FindIt 基准（arXiv 2606.04282）对 InternVL3 的最优形态记为
`xyxy / JSON / coordinates`，即坐标**直接给数值**、不用 `<box>` 标记。

### 3.3 适配器改动（仅此三处，均须声明）

1. **提示词**：换成上述 InternVL 接地句式（**这是跨族的必要适配，也是本件"新机制"的来源**）
2. **解析器**：新增一个只认"裸数组 `[[x1,y1,x2,y2]]`"的解析分支，产出与现行完全相同的
   `{bbox, n, raw}` 记录格式
3. **闸门**：与 `_assembly_32b.py` **完全一致**（互斥六桶：无框 / 退化逆序 / 面积>0.35 /
   面积过小 / 与基线一致 / ★改动），**不新增任何判据**

> 纪律：**解析器改动必须能被机器验证**——上线前用同一段文本双向喂两个解析器，
> 确认"0–1000 整数 → 归一化浮点"的换算逐位相同。

## 5. 两段式执行：先小样（跨族硬要求），后全量

### 第 1 段（小样 200~300 条，分层随机，**样本先冻结后测**）

| 判据 | 通过条件 | 依据 |
|---|---|---|
| **① 改动率** | **≥ 0.168**（= 769 ÷ 4587） | 若先验可用，这是够到 0.8 的**必要条件**；低于此则本层在量级上补不上缺口 |
| **② 性质** | 改动条目与基线的 IoU **不能大量 < 0.3** | 判据②已被两次实测验证为有效诊断：健康 → 先验适用（B′ **+16.1%**）；p50=0.000 → 重掷（三模态 **−3.1%**） |

**两条都过 ⇒ 才允许套用 17.3% 先验做全量预期；任一不过 ⇒ 判死，不做全量。**

> 说明：跨族无可用先验，而离线无法测"净翻转"。判据②的作用正是**在提交之前**
> 判断新模型的框是"更准的升级"还是"另一次独立猜测"——这就是它的用法。

### 第 2 段（全量 4587 条）

## 6. 事前预期（**写定后不得修改**）

**本件不给正的事前预期**——跨族先验不可迁移，凭直觉给正数是 D 那次已经犯过的错。
替代做法：**先写条件式预期**，其条件由小样判据决定。

| 情境 | 预期 |
|---|---|
| 判据 ① 或 ② 不过 | **不做全量**（止损） |
| 两条均过，改动率实测 r | 改动面 = 4587 × r；净翻转 ≈ 改动面 × 17.3%（**此时才允许套用**） |
| 参考：r = 0.168 | 改动面 769 → +133 → **0.8000** |
| 参考：r = 0.10 | 改动面 459 → +79 → 0.7905 |

**风险（事先声明）**：即使两条判据都过，跨族仍可能整体更差——
判据②只排除"重掷"，**不能排除"系统性地比基线差"**。故全量件必须自身即为可回退的测量件
（序数层锁定 + 未改条目锁定），且提交后按 `得分 × 5690 − 689` 读数。
