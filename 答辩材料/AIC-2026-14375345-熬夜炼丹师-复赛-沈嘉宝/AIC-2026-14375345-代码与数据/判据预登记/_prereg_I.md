> 本件为新立预登记，不修改 `_frozen_criteria.md`（`D4A4BC35…`）等任何既有冻结稿。

## §1 动机

当前最高 **0.7786**，离 0.8 差 **122 条**。已关闭：跨机制替换（5/5 全负）、
H 枚举+几何选择（Δ=0）。**唯一曾为正的机制是"同族模型升级"**：
8B→32B direct **+82 条/17.6%**；AWQ→bf16 direct **+11 条/9.9%**（幅度随干预强度递减）。

本件即沿用该机制（**direct 框替换 direct 框**），把模型换成 **Qwen3.8-27B**（Apache-2.0，开源可本地部署）。

## §2 ★先验：**不可迁移，不给正预期**

项目的迁移条件（`_frozen_criteria__跑后实录.md` §三）是：
**「被替换那一层的性质 + 模型是否真升级」二者同时成立**。

| 条件 | 本件 | 判定 |
|---|---|---|
| 被替换层是 direct 框层 | 是（32B bf16 direct） | ✓ |
| 模型**真升级** | **未证实** | **✗** |

理由：Qwen3.8-27B 官方 benchmark 全为编码/agent/推理（SWE-bench、Terminal Bench、GPQA…），
**没有任何视觉接地（grounding）指标**。参数量 27B < 32B，
且是**跨代新架构**（Gated DeltaNet + Gated Attention 混合，64 层里 48 层线性注意力）。

⇒ **迁移条件只满足一半 ⇒ 先验不可迁移。**
**本件事前预期：不给正数，可能为负。**

（对照教训：先验跨机制迁移曾 4/4 全负，并出过 6σ 偏离——预期 +12 实测 −7。）

### ★ G3 口径重述（**2026-10-03，下载完成前、任何推理之前**）

原写"方向正确 ≥ 12/20"。**该阈值取自 bf16 阶段**，而那一阶段模型是**同族升级、有先验**；
本件是**跨代新架构、无接地先验**，沿用同一阈值等于用"质量闸门"去管一件"能力存在性"未知的事。

**重述后的判据（两档）**：

| 方向正确 | 处置 |
|---|---|
| **≥ 12/20** | 通过，按正常流程走全量 |
| **8 ~ 11/20** | **放行全量，但登记为「接地能力弱」**；结果解释时不得读作"模型升级" |
| **< 8/20** | **停**，不出件（能力存疑，不值得烧全量与提交名额） |

**重述的理由（写在此处，避免事后调阈值）**：

1. 闸门的**目的**变了：跨代模型要验的是"**能不能接地**"，不是"接得好不好"——后者由线上读数回答。
2. **下行风险已被规则封住**：平台按**历史最高分**记录，本件若差只损失一次提交名额，
   不拉低 0.7786。故闸门不必为"质量"兜底，只需为"能力存在性"兜底。
3. `< 8/20` 仍保留硬停：低于此说明连粗定位都不成立，不值得投入。

**同时把"方向正确率"作为诊断量完整报出**（含 8~11 档的分条明细），供全量后解释用。

### ★ 本件**不是到 0.8 的路径**（写进判据，防误读）

```
Qwen3.8-27B 是 27B（< 32B）、跨代新架构（64 层里 48 层线性注意力）、且**无任何接地指标**。
它不是"升级"，而是一次**「跨代新架构能不能至少不倒退」的测试**。
出件后不得被读作"换了更强的模型"。
即使它为正，其正数也不可迁移到"跨代优于同族"这个结论上。
```

| `flash-linear-attention` | ✓ 0.5.2 已装（**导入名是 `fla`**——先前记的 `flash_linear_attention` 是我写错，导致误判为"缺"） |

### 新增待验风险：cu130 驱动兼容性

新 venv 的 torch 为 **2.11.0+cu130**（CUDA 13.0），而旧 venv 为 2.8.0+cu128。

```
驱动 ≥ 580 ⇒ cu130 可用，不必改动
驱动 < 580 ⇒ 需改装 torch 的 cu128 构建（可能触发重新 pip install）
```

**该风险在下载期间查（`/proc/driver/nvidia/version` 与 `nvidia-smi` 头部），
结果记入本件**；若需换构建，在起服前完成。

### ★ 风险实测结果（2026-10-03，起服阶段）

驱动 **580.126.09 ≥ 580 ⇒ cu130 判定可用**，但实测**起服仍然失败一次**，
原因不是 torch 构建，而是 **custom all-reduce 内核**：

```
(Worker_TP1) INFO [gpu_model_runner.py:6412] Profiling CUDA graph memory: ...
Failed: Cuda error /workspace/csrc/custom_all_reduce.cuh:455 'invalid argument'
(EngineCore) ERROR [multiproc_executor.py:284] Worker proc VllmWorker-1 died unexpectedly
(EngineCore) ERROR [core.py:1195] RuntimeError: Engine core initialization failed.
```

排查证据（排除法）：

| 假设 | 证据 | 判定 |
|---|---|---|
| 共享内存不足 | `/dev/shm` = 16 G，仅用 36 K；`shm_broadcast` 那条 60 秒警告出现在 TP1 已死之后 | **否**（是后果） |
| 拓扑/P2P 不通 | `nvidia-smi topo -m` = **NV12（NVLink）**；`torch.cuda.can_device_access_peer(0,1)=True` | **否** |
| 架构/权重问题 | 同一日志里 `Resolved architecture: Qwen3_5ForConditionalGeneration`、`Model loading took 25.61 GiB`、torch.compile 均成功 | **否** |

⇒ 判为 **custom all-reduce 在 cu130 + A100(cc8.0) + 驱动 580 组合上的兼容性问题**。

**处置**：按 vLLM 源码自身的建议（`custom_all_reduce.py:104/152/163` 在探测不适配时
即提示"specify disable_custom_all_reduce=True explicitly"），加 `--disable-custom-all-reduce`，
**退回 NCCL all-reduce**。这是 **TP 通信的基础设施路径替换**，不触及提示词 / 解码 / 并发
（§3 的 M5 单变量前提不受影响）；已在起服脚本中固化为 `Q38_NOCAR=1`（默认开）。

**副作用登记**：NCCL 与 custom all-reduce 的归约结合顺序可能不同，理论上会带来
末位级浮点差异；本件的判据（G2/G3 与线上读数）不依赖逐位复现，故不影响结论。
