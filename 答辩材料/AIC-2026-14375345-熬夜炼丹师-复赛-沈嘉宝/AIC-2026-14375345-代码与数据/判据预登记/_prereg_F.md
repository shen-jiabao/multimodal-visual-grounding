## 2. 机制与它的硬天花板（★本件最重要的一条）

```
WeDetect-Base-Uni → top-100 候选（像素 xyxy）
        ↓ 连同原图一起喂给 VLX-Seek
VLX-Seek-1.5-10B → 只输出**区域引用**（<obj3> 这样的编号），不输出坐标
        ↓ 官方 `_build_result_bbox_list` 用编号回查候选表
        得到我方基线口径的 0-1 归一化框
```

**模型只做"选"，不画框。** 已从源码逐行核实（`vlx_seek_worker.py:113-144`、
`predict()` 于 `:200-262`）：

- `predict()` 先 `_order_boxes()` 把候选排序并记录 `sorted_to_original`；
- `_remap_object_tokens()` 把模型答的**内部序号**映射回**调用方序号**；
- `_build_result_bbox_list()` 再用调用方序号索引 `caller_boxes`。

⇒ 返回的坐标**必然等于我们喂进去的某个候选框**，且编号映射无歧义。
⇒ **输出质量被 WeDetect 的候选质量硬性封顶**：目标不在候选表里，永远选不出来。

**因此本件的读数必须解释为「检测器能力 × 选择能力」的乘积**，不可单独归因于语言模型。

## 3. 输出与坐标口径（★已核实）

| 项 | 值 |
|---|---|
| 调用 | `VLXSeekWorker(model_path, device="cuda").ground(image, bbox_list, description)` |
| 任务模板 | `grounding_single`（官方 `run_task` 内建） |
| 传入坐标 | **原图像素**（非 0–1000、非 0–1）⇒ 我方 0-1 基线框须 ×(W,H) |
| 传出坐标 | 同为**原图像素** ⇒ 须 ÷(W,H) 并夹到 [0,1] |
| 回包字段 | `{"answer", "result_bbox_list", "prompt_tokens", "completion_tokens"}` |
| `result_bbox_list` 元素 | `{"object_index", "xmin", "ymin", "xmax", "ymax", "label"}` |
| 无框条件 | `answer` 中不含 `<ground>…</ground><objects><objN></objects>` ⇒ 空表 |

**★已声明的偏离（不隐瞒）**：官方 `predict()` 默认 `temperature=0.2`（`do_sample=True`，
随机采样）。本件缺省用 `--temp 0.0`（贪心）——理由是读数须可复现、且 20 条冒烟闸门
不应被采样噪声撞翻。若要严格照官方默认，加 `--temp 0.2`。**此偏离写在跑之前。**

**★已声明的固有开销**：官方 `load_wedetect_proposals()` **每次调用都重建检测器**
（`torch.load` 414 MB + `load_state_dict` + `.cuda()`）。我方仅按图缓存候选表，
装载次数 = 图片数 1295，无法在不改官方代码的前提下免除。冒烟时会计时量化。

## 5. 事前预期（**写定后不得修改**）

**本件不给正的事前预期。** 两条独立理由：

1. **同源范式已实测为负**：VLX-Seek 的"候选枚举 → 叠编号 → 选编号"与序数层 SoM
   **同源**，而后者实测 **−10.6%**（66 改动 / −7）。
2. **跨族/跨机制在本项目 4/4 全负**（8B 提示合并 −24.8%、GD 候选池 −18.6%、
   深度轴 −23.1%、序数 SoM −10.6%）。凭直觉给正数是 D 那次已犯过的错。

**条件式预期**（唯一允许的量化方式）：

| 情境 | 预期 |
|---|---|
| 冒烟 ① 或 ② 不达 | **不做全量**（止损） |
| 两条均过，装配后实际改动面 N | 不给正数；**只看读数**：`得分×5690 − 689` vs 对照 **3730** |

> 反过来说清本件的**真实性质**：它是一次**换范式的探路**，不是一次有先验支撑的加杠杆。
> 即便读数为负，只要 `Δ` 能干净归因（序数层锁定 + 未改条目锁定），
> 它就把"选候选范式在本赛题上值多少"这个未知量**变成已知量**——这是本件的主要产出。
