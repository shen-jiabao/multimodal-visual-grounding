## §1 复现标准

### 1.1 什么必须一致（否则不是复现）

1. **提示词逐字一致**（见 §7.1）——提示词差异会与模型差异混在一起，无法归因。
2. **解码一致**：`temperature=0.0`（贪心）、`max_tokens=256`。
3. **并发一致**：`QWEN_CONC=8`（与交付件同）。
4. **几何守卫一致**：`MAX_AREA=0.35`、`MIN_AREA=1e-5`、`IOU_KEEP=0.5`（见 §7.3）。
5. **作用域判据一致**：只动"非序数 4587 条"，序数 1103 条**逐位不动**（脚本有硬断言）。
6. **方法论纪律一致**：§6 的五条。

### 1.2 什么可以不同

- 模型权重可从任意镜像下载（**校验逐分片 SHA256 即可**，见 §3.3）。
- 机器/驱动/框架小版本可不同（但 vLLM 有**下界**要求，见 §2）。
- 中间产物的**顺序**可以不同（脚本支持断点续跑）。

### 1.3 为什么不能保证字节级相同（如实说明）

- **离线段（CPU）**：确定性，**可逐字节重建**（几何原语、规则层、装配、校验均无随机性）。
- **推理段（GPU）**：不保证。`bfloat16` 下的浮点归约顺序随**硬件、驱动、cuDNN/flash-attn 版本**变化；
  即使代码与权重完全相同，产出也可能有少量坐标差异并向下游传播。
  **本项目实测过同类现象**：同条件复跑曾出现 4/30 条坐标差 0.001 的抖动（复跑即消失）。
  ⇒ 故本手册的验收标准是**"分数同量级 + 各级改动面同量级"**，而不是 SHA 相同。
  （交付件自身的 SHA256 见 `README.md` §6.5，用于确认"你手上的就是那一份"，不是复现目标。）

### 1.4 验收指标（怎么判断复现成功）

| 级别 | 指标 | 期望 |
|---|---|---|
| 单条推理 | 抽样 20 条与随包产物比对 | 大多数逐位相同；少数 IoU ≥ 0.99 |
| 改动面 | 装配器打印的 `★改动` 条数 | 与 §5 各级给的历史值同量级（±20%） |
| **总分** | 线上 ACC@0.5 | 与历史值差 **±0.005 以内**（≈ ±30 条）视为成功 |

**必须加的两个参数**（脚本已固化，手工起服时别漏）：

| 参数 | 为什么 |
|---|---|
| `--disable-custom-all-reduce` | `cu130 + A100(cc8.0) + 驱动 580` 组合下 custom all-reduce 内核在 CUDA graph 捕获阶段崩：`custom_all_reduce.cuh:455 'invalid argument'` → TP1 死 → `Engine core initialization failed`。拓扑与 P2P 均正常，退回 NCCL 即可。**不影响提示词/解码/并发** |
| `--limit-mm-per-prompt '{"image":1,"video":0}'` | 否则编码器按"最大尺寸视频"做探测，一次性分配 5.77 GiB 而 OOM（实测 budget 从 151250 降到 16384 tokens） |

另建议 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`（缓解碎片）。

**起服自证**（防起错模型——本项目把这条做成硬断言，因为起错模型会让读数完全无意义）：

### 4.4 装配出件（**读数三锚点必须对齐**）

```bash
python code/_assembly_32b.py --direct qwen38_direct.json \
    --base result_semi_n32bf16_nonord --base-score 0.7786 \
    --ord-correct 689 --base-correct 3741 \
    --stem result_semi_q38_nonord --zip
```

三个锚点的含义与**为什么必须一起改**：

| 参数 | 含义 | 本件取值 |
|---|---|---|
| `--base-score` | 基线件的线上得分 | 0.7786 |
| `--ord-correct` | 该阶段**序数层**的正确条数 | 689 |
| `--base-correct` | 该阶段**非序数桶**的正确条数 | 3741 |

> ★这三者是**同一阶段**的量，必须成套使用。本项目踩过一次：
> 序数锚点 689 是 **0.7766 阶段**测出的；若换成更高分的基线却沿用旧锚，
> 打印出来的读数公式就是错的（细节见 README §6.4 第 9 条）。
> 关系式：`0.7786 × 5690 − 689 = 3741`。

**装配器的六桶是互斥的，且带总和断言**（这是把"承诺"变成机器可检查的东西）：

```
1 无框 → 保留基线          模型输出 [] ⇒ 留空必错，基线框至少还有猜中的机会
2 框退化/逆序 → 保留基线
3 面积 >0.35 → 保留基线     视为"合并了多个目标"的宽框
4 面积 <1e-5 → 保留基线
5 与基线一致(IoU ≥ 0.5) → 不动
6 ★改动
断言：六桶之和 == 4587，否则直接失败
```
本交付件的实测桶分布：`329 / – / 100 / – / 3639 / 519`（合计 4587 ✓）。


## §5 【路径乙】全链复现（从数据到答案 zip）

> 本节是**完整流程**。全链 = **6 级 = 6 次独立提交**，逐级推进。
> 每一级给出：目的、输入、精确命令、输出、期望读数、校验点、失败定位。

### 5.0 ★ 先看依赖图：哪几级可以完全离线复算

**这张表决定你的工作量。** `L2` 与 `L4` 两级所需的一切产物**全部随包**，
**零 GPU、零下载**即可复算并核对；`L1 / L3 / L5 / L6` 需要重跑对应模型的推理。

| 级 | 产出件 | 线上分 | 该级输入 | 输入随包？ | 需 GPU |
|---|---|---|---|---|---|
| L1 | `result_final_semi` | 0.7459 | 数据集图像 + `Qwen3-VL-8B-Instruct`（LA 可选） | 图像/权重不入包 | ✅ |
| **L2** | `result_semi_ord_det` → … → `result_semi_enum_trunc` | 0.7552 → **0.7598** | `_semi_qwen3vl_all.json`、`_semi_qwen3vl_som_all.json`、`_enum_raw.json`、`_enum_targets.json`、L1 件 | **全部随包 ✓** | **❌ 纯 CPU** |
| L3 | `result_semi_n32_ordbase` | 0.7742 | 数据集图像 + `Qwen3-VL-32B-Instruct-AWQ` | 权重不入包 | ✅ |
| **L4** | `result_semi_n32_orddirect` | 0.7766 | L3 件、`_semi_qwen3vl_all.json`、`_qwen32b_direct_ord.json` | **全部随包 ✓** | **❌ 纯 CPU** |
| L5 | `result_semi_n32bf16_nonord` | 0.7786 | 数据集图像 + `Qwen3-VL-32B-Instruct`（bf16） | 权重不入包 | ✅ |
| L6 | `result_semi_q38_nonord` | **0.7963** | 数据集图像 + `Qwen3.8-27B` | 权重不入包 | ✅（2×40 GB） |
| **L7** | `result_semi_k72b_n519` | **待定** | 数据集图像 + `Qwen2.5-VL-72B-AWQ` | **产物随包 ✓** | 仅首次推理需 ✅（2×40 GB） |

**建议顺序**：先跑 **L2 → L4**（离线，立刻能验证两套核心判据：**序数规则层**与**同机制替换**），
再决定是否下载权重做 L1 / L3 / L5 / L6。

**方法论点（很重要）**：每一级都是"在上一级的件之上做**单变量替换**"，
且随包已把所有中间件按得分归档 ⇒ **你可以从任意一级的随包基线件接续，不必从 L1 从头跑**。

### 5.1 每一级的共同动作（五步，逐级套用）

**Step 1｜跑该级脚本** → 得到 `out` 字典（5690 条）

**Step 2｜看脚本自带的自检**（这些是 `assert`，失败即抛异常、**不会静默出件**）：
- 分类桶**互斥**且总和 == 作用层条数
- **序数层 1103 条逐位未动**（若该级只改非序数）
- **非序数 4587 条逐位未动**（若该级只改序数）
- 未提供证据的条目逐位未动

**Step 3｜出件并校验**：
```bash
python code/_validate_semi.py <你的 zip>
#    期望 4/4 通过、退出码 0
```

**Step 4｜提交 → 按口径读数 → 记入谱系**（`submission_zips/semifinal/SHA256.txt`）：
```
提交分 = (该层正确数 + 其余层正确数) / 5690
1 条 = 0.000176 分
```

**Step 5｜把产物归档到 `submission_zips/semifinal/<四位得分>/`**，文件名与壳名一致
（例：`0.7963/result_semi_q38_nonord.json`），并在 `SHA256.txt` 追加一行指纹 + 读数推导。

> 平台按**历史最高分**记录 ⇒ **逐级推进无下行风险**（某级变差只损失一次提交名额）。

### 5.1b 服务怎么起（本链共四档，同一套机制）

**共同机制**（四档只有"权重目录 / 服务名 / TP / 环境变量名"不同，起服实现只有一份）：
① **目录名断言**（必须含目标型号、不得含易混型号）——防起错模型让读数作废；
② **TP 自动判定**（按单卡显存与权重体积）；③ **attention 后端逐个重试**；

## §6 方法论纪律（**五条，复现时一并复现**）

这五条是本项目最有分量的产出，**不做这五条，复现出来的分数无法解释**：

1. **判据在跑之前写定**。作用域、闸门、事前预期、止损线，全部先写进预登记文件
   （本项目为 `_prereg_*.md`），然后再跑。**禁止事后调阈值**。
2. **单变量隔离**。每件只改一层，其余层**逐位不动**，并用**硬断言**（不是"构造上应该不动"）
   验证。这样得分差才能干净归因。
3. **归零法测量**。赛题不给真值，某子集的真实正确条数只能"测"：交一件把该子集框换成
   **必然错的角落小框**（面积 1e-4）的测量件，其余原样保留；平台按**历史最高分**记录
   （测量件不拉低成绩），返回的得分直接读出答案：
   ```
   得分 × 5690 = 序数层正确数 + 其余层正确数
   ```
   诱饵框必须**极小且贴角**——不能用整幅框（真值面积 ≥0.5 的条目会被误算为正确）。
4. **闸门先于全量**。20 条冒烟不过就不烧全量（G2 机检 + G3 人眼）。
5. **止损线先写**。例如"某方向 Δ ≤ 0 ⇒ 封口，记入族谱"。本项目据此关闭了多条全负路线。

> 另外一条重要的**血泪教训**：**"同机制"是可判定条件，不是感觉**。
> 跨机制替换（direct 基线 → SoM / 检测器候选）在本项目 **5/5 全负**（−10.6%、−18.4%）；
> 同机制（direct 框替换 direct 框）四次全正（9.9% ~ 19.4%）。
> 替换前请先算一次 `IoU(基线, 拟替换来源)`。

## §9 已知坑速查（复现者可直接避让）

1. `transformers` 必须 `< 5.0`（见 §2.2）。
2. 交付件级模型需 `vLLM ≥ 0.22.1`（见 §2.2）。
3. **A100 上必须 `--disable-custom-all-reduce`**（见 §4.1）。
4. **必须 `--limit-mm-per-prompt '{"image":1,"video":0}'`**，否则编码器探测即 OOM（见 §4.1）。
5. flashinfer 的 JIT 需要 nvcc：pip 版 CUDA 只装 `libX.so.N` 而不装 `libX.so`
   ⇒ `-lcudart` 找不到。需批量补 `libX.so → libX.so.N` 符号链接，并把 pip CUDA 链到
   `/usr/local/cuda`（flashinfer 的默认回退路径）。
6. **数据集有两个格式子群，赛题文档只描述了其中一个**：被引用 1295 张里 **97 张（7.5%）**
   是 640×360 的 `.jpg` 组，其深度为 `RGB` 三通道且**逐像素相同**（实为 8 位灰度）。
   直接把 3 维数组交给 `Image.fromarray(arr, mode="L")` 会抛
   `ValueError: Too many dimensions: 3 > 2`，**使那 97 张整批失败**。
   对 `.jpg` 组应**直通原值、不按未知比例缩放**（赛题语义只需"越亮越远"的单调性）。
7. **新版 PIL 不容忍逆序矩形**（`x1 > x2` 会抛 `ValueError`）；`draw_som` 已对**绘制用**矩形
   做角点排序，候选表与编号映射不经过该处（机制未变）。
8. **覆盖率优先**：模型对约 7~9% 的条目输出 `[]`（认为图中无该物体），这类条目**必须保留基线框**
   ——留空必然错，基线框至少还有猜中的机会。
9. **别用"跑了一半的前缀"外推改动面**：按图名排序的前缀里分歧条目更密，会系统性高估约 10%。
   要估计改动面请用**分层随机小样**（实测 300 条分层随机：预测 0.077 / 实测 0.077，几乎逐位命中）。
10. **派生读数的锚点必须与基线件的"阶段"对齐**（见 §4.4）。
