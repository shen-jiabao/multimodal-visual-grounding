## 1 任务与方案概述

### 1.1 任务定义

给定同一场景的**可见光（visible）/ 红外（infrared）/ 深度（depth）**三模态图像，以及一条描述目标的英文查询，输出该目标在可见光图像中的**归一化边界框** `[x1, y1, x2, y2]`（x1/y1 为左上角、x2/y2 为右下角，均由像素坐标除以图像对应的宽 / 高得到，取值范围 0~1）。

评测指标为 **ACC@0.5**：预测框与真实框的交并比 IoU ≥ 0.5 记为该条正确，最终得分为正确条数占总查询数的比例。复赛规模为 **5690 条查询 / 1295 张图**。

### 1.2 方案一句话

**不做端到端训练**：以开源多模态大模型承担**感知（直接定位）**，以**确定性规则**承担**推理（序数指代）**，以**带断言的装配器**承担**出件**。

具体地：以 Qwen3-VL 系列（8B / 32B-AWQ / 32B-bf16）与跨代模型 Qwen3.8-27B 对**非序数 4587 条**做直接定位；对**序数 1103 条**启用"查询文本程序化推算 + Set-of-Mark 选号"四层叠加；每一条新证据都只在**同机制**前提下替换上一层的框，改动范围经硬断言隔离；出件前经**六桶互斥装配器**与**硬约束校验器**把关。

### 1.3 合规要点

- **模型**：全部为开源模型（Qwen3-VL 系列、Qwen3.8-27B、LocateAnything-3B），本地/私有云部署，**全程未调用任何闭源在线推理 API**；
- **数据**：仅使用赛事官方提供的测试集推理，**未使用外部数据、未对测试集做任何标注**；
- **推理**：结果全部由算法自主推理产出；后处理为**确定性规则**，可由管线逐条复算。

## 2 数据集

### 2.1 规模与模态

| 项目 | 内容 |
| --- | --- |
| 图像规模 | 1295 张场景图像（三模态各 1295 张，缺失 0、损坏 0） |
| 查询规模 | 5690 条查询（多查询 / 图） |
| 查询分层 | **序数类 1103 条**（19.4%，如"从右数第二个"）＋ **非序数 4587 条** |
| 输出格式 | `Query ID → {visible, infrared, depth, query, bbox}` |

三模态特性与其对方案的约束：

- **可见光**：三通道 8 位 RGB，提供外观纹理与色彩，是主要定位依据，但弱光场景细节损失严重；
- **红外**：实质为单通道热辐射灰度图的三通道堆叠，像素值越高表示温度越高；在可见光失效的弱光场景中可突显活体与热源轮廓，是主要补充模态；
- **深度**：单通道 16 位，单位毫米，相机可感知距离约 300~19999 mm；数值为 0 或过小表示无效区域。深度提供目标与相机的空间距离，可用于区分"近处 / 远处"这类空间指代。

### 2.2 数据格式发现（赛题文档未记载）

实测复赛数据集存在**两个格式不同的子群**，赛题文档只描述了其中之一：

| 子群 | 被引用 1295 张中 | 分辨率 | 深度存储 | 红外 |
| --- | --- | --- | --- | --- |
| `.png` 组 | **1198** | 1920×1080 | `I;16` 单通道 uint16、单位毫米、实测 0–19999 | PNG，三通道近似相同 |
| **`.jpg` 组** | **97（7.5%）** | **640×360** | **`RGB` 三通道且逐像素相同** → 实为 8 位灰度；JPEG 有损、原始 16 位量程不可还原 | JPEG，三通道完全相同 |

- 两个子群**内部**三模态同尺寸 → **跨模态对齐性不受影响**；
- **工程陷阱**：把 3 维数组直接交给 `Image.fromarray(arr, mode="L")` 会抛 `ValueError: Too many dimensions: 3 > 2`，**使那 97 张（7.5%）整批失败**；
- **处置**：对 `.jpg` 组**直通原值、不按未知比例缩放**——赛题语义只需"越亮越远"的**单调性**，8 位原值已满足；按未知比例换算成毫米等于凭空造信息。零回归验证：`.png` 组新实现与旧规则输出**逐位相同**。

## 3 技术路线

### 3.1 总览

```flow
[1] 输入：queries.json（Query ID → 三模态路径 + 查询文本）
▼
[2] 分层：序数层 1103 条 ｜ 非序数层 4587 条（唯一作用层）
▼
[3] 非序数层：大模型直接定位（Qwen3-VL / Qwen3.8-27B）
▼
[4] 序数层：查询文本程序化推算 + Set-of-Mark 枚举选号（四层叠加）
▼
[5] 装配器：六桶互斥 + 总和断言（只接受同机制、合法、更优的改动）
▼
[6] 硬约束校验：条数 / 键集 / 字段回显 / bbox 合法性
▼
[7] 输出：result_semi_q38_nonord.zip（内部 JSON，5690 条）
```

### 3.2 主模型推理（分层 + 单变量替换）

非序数层的每一级都是"在上一级的件之上做**单变量替换**"：提示词、解码（`temperature=0` 贪心）、并发（`CONC=8`）与上一级**逐字相同**，只换模型或精度。这样得分差才能干净归因。

| 级 | 模型 | 被替换的那一层 | 改动面 → 净翻转 | 净成功率 |
| --- | --- | --- | --- | --- |
| L3 | Qwen3-VL-32B-Instruct-AWQ | 8B 直接框 | 467 → **+82** | **17.6%** |
| L5 | Qwen3-VL-32B-Instruct（bf16） | 32B-AWQ 直接框（同族精度修复） | 111 → **+11** | **9.9%** |
| **L6** | **Qwen3.8-27B**（跨代换模型） | 32B 直接框 | **519 → +101** | **19.4%** |

**L6 即本交付件的来源**：提示词 / 解码 / 并发与 L5 逐字一致，仅把非序数层换成 Qwen3.8-27B 的输出，经装配器替换 **519** 处，线上得分由 0.7786 升至 **0.7963**（`Δ = +101 条 = +0.0177`，零假设 σ≈11.4 → **8.8σ**）。

**起服要点（实测踩坑，已固化在 `code/remote_shell/_get_serve_q38.sh`）**：

- `--disable-custom-all-reduce`：`cu130 + A100(cc8.0) + 驱动 580` 组合下 custom all-reduce 内核在 CUDA graph 捕获阶段崩溃，退回 NCCL 即可；**不影响提示词 / 解码 / 并发**；
- `--limit-mm-per-prompt '{"image":1,"video":0}'`：否则编码器按"最大尺寸视频"探测，一次性分配 5.77 GiB 而 OOM；
- `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`：缓解显存碎片。

### 3.3 序数层确定性规则（四层叠加，各层改动集互不相交）

序数层是全项目最弱层（基线准确率 61.2%），改用**查询文本程序化推算**替代模型猜测：

| 层 | 含义 | 改动面 → 净翻转 |
| --- | --- | --- |
| `det` | 水平轴**文本推算**（从查询里的序数词推"第 k 个"该在哪） | 136 → **+53** |
| `selfsort` | 候选**自排序**（枚举候选按位置重排后再取第 k 个） | 41 → **+9** |
| `qfb` | **回退点改用直接框**（推算失败时不再用 SoM 选号） | 47 → **+3** |
| `yaxis` | **垂直轴**序数（上下方向的"第 k 个"） | 10 → **+3** |
| `trunc` | **枚举截断组修复**（枚举召回不足者换提示词重跑并合并） | 52 → **+11** |

五层之和 53+9+3+3+11 = **+79 条**，与线下序数层 596 → 675 的实测逐条吻合。

序数层还做过一次**同机制替换**（B′，L4）：判据是 `IoU(基线框, 8B 直接框) ≥ 0.999`（→ 该条的当前框确实来自一个 direct 定位器），筛出 **343 条**；替换 87 处 → 净 **+14**（**16.1%**）。

### 3.4 装配器（六桶互斥 + 总和断言）

把"承诺"变成机器可检查的东西——每个非序数条目严格落入且仅落入一桶：

| 桶 | 判据 | 处置 |
| --- | --- | --- |
| 1 | 模型输出无框（`[]`） | **保留基线**（留空必错，基线框至少还有猜中的机会） |
| 2 | 框退化 / 逆序 | 保留基线 |
| 3 | 面积 > 0.35 | 保留基线（视为"合并了多个目标"的宽框） |
| 4 | 面积 < 1e-5 | 保留基线 |
| 5 | 与基线一致（IoU ≥ 0.5） | 不动 |
| 6 | ★ 改动 | 采纳新框 |

断言：**六桶之和 == 4587**，否则直接失败、不出件。**本交付件（L6）的实测桶分布为 `329 / – / 100 / – / 3639 / 519`（合计 4587，互斥口径自检通过）**。

### 3.5 后处理与提交格式

- bbox 归一化到 `[0,1]`，坐标 `round` 至 4 位小数；非法 / 缺失输出回退到占位框 `[0.49, 0.49, 0.51, 0.51]`；
- 每查询条目**四字段（visible / infrared / depth / query）逐条原样回显**，仅 `bbox` 为预测值；
- 结果压为 zip 提交（`zip 内 JSON 名 == zip 基名`）。

## 4 关键方法与验证手段

赛题**不提供 `test.json`（无任何真值）**，故本项目以四条纪律把"看不见的准确率"变成可判定的读数：

### 4.1 预登记（判据写在跑之前）

作用域、闸门、事前预期与止损线，全部**先写进预登记文件**（`_prereg_*.md`）再跑，**禁止事后调阈值**。

### 4.2 单变量隔离（硬断言，而非"构造上应该不动"）

每件只改一层，其余层**逐位不动**，并由脚本 `assert` 验证（例如只改非序数时，断言序数层 1103 条逐位相同）。这样得分差才能干净归因。

### 4.3 归零法（zeroing measurement）

交一件把**某个子集**的框换成**必然错的角落小框**（面积 1e-4）的"测量件"，其余子集保留真框；平台按**历史最高分**记录（测量件不拉低成绩），返回的得分**直接读出**其余子集的真实正确条数。诱饵框必须**极小且贴角**——不能用整幅框。

读数口径是**恒等式**：

```text
提交分 = (非序数正确条数 + 序数正确条数) / 5690
Δ得分 × 5690 = 净翻转条数          1 条 = 0.000176
```

### 4.4 闸门先于全量

20 条冒烟不过就不烧全量：**G2**（机检，`bbox` 可解析 ≥ 16 / 20）＋ **G3**（人眼，框是否落在查询描述的目标附近，三档判据**事前**写定）。

## 7 创新点

1. **分层解耦 + 同机制替换的量化判据（本项目最有分量的产出）**：把"能否把一个模型的先验迁移到另一层"变成可判定条件——

   | 杠杆 | 被替换的那一层 | 是否同机制 | 改动面 | 实测净成功率 |
   | --- | --- | --- | --- | --- |
   | 非序数 32B 重跑 | 8B 直接框 | 是 | 467 | **+17.6%** |
   | 序数层 B′ | 8B 直接框 | 是 | 87 | **+16.1%** |
   | AWQ → bf16 精度修复 | 32B-AWQ 直接框 | 是 | 111 | **+9.9%** |
   | 跨代换模型 Qwen3.8-27B | 32B 直接框 | 是 | **519** | **+19.4%** |
   | 同模型三模态输入 | 32B 直接框 | 是（但重掷） | 128 | **-3.1%** |
   | 序数层 SoM | 8B 直接框 | 否 跨机制 | 66 | **-10.6%** |
   | VLX-Seek 替换非序数 | 32B 直接框 | 否 跨机制 | 846 | **-18.4%** |

   **判据**：① **同机制是必要条件**——跨机制在本项目 **5/5 全负**；② **"模型真的更强"不是必要条件**——Qwen3.8-27B 参数更小、跨代、官方无接地指标，实测却是四次同机制测量中最高的一次（+19.4%，8.8σ）；③ 真正起作用的是「**框层性质相同 ＋ 新模型的框与原层足够不同**」，差异本身就是收益来源。

2. **把"没有真值"变成可判定读数**：预登记 + 单变量隔离件（硬断言）+ 归零法测量 + 先于全量的 G2/G3 闸门，四条纪律共同构成一套在无真值条件下仍可复算、可审计的实验方法。

3. **确定性规则承担推理**：序数指代交给"查询文本程序化推算 + 候选自排序 + 轴上投影"四层规则（净 +79 条），而非交给模型猜测——可解释、可复算、无随机性。

4. **工程鲁棒性**：识别并处置了数据集"两个格式子群"（`.jpg` 组深度实为 8 位灰度、且不可按未知比例还原）这一赛题文档未记载的陷阱，避免了 7.5% 条目整批失败。

## 8 不足之处（如实陈述）

1. **仍未达 0.8**：当前最高 **0.7963**，距 0.8 差 **21 条**（按实测 19.4% → 需约 109 条改动面）。序数侧上限被**作用域**锁死：序数层现存错题中约 760 条的来源是 SoM / det 推算 → 替换它们属**跨机制**（本项目 5/5 全负），唯一有正先验的机制够不着。继续提升需再引入一个"与当前层足够不同"的定位模型。
   **★ 这一条同时是本次最主要的不足**：事前把"官方有没有接地指标"当成"模型是否更强"的**代理**，据此对跨代换模型给出"不给正数"的判断，实测却是全部干预中最高的一次。代理失效、判断偏保守，是方法学上的实质失误。
2. **"可迁移范围"被后续实测进一步收窄**：追加一次同机制替换（异质模型 72B-AWQ 只补"最新模型未采纳的 429 位"）得到 **-16.4%**。→ 机制规律应收窄为：**只有"框源本身是 VLM 直接输出"的位置可迁移；对"补框链工程化填充"做替换属跨机制、为负**。"补漏通道"在结构上是空的。
3. **三模态未被有效利用**：赛题规定的算法输入是三模态，而本方案主体管线**只使用可见光**。实验证明给同一模型多喂红外与深度**不产生增量**（改动率 0.077 远小于 所需 0.465，且改动条目与基线 IoU 中位数为 0 → 重掷）。**跨模态融合是尚未突破的方向。**
4. **无真值**：全部结论依赖线上提交的单一标量反馈，无法做细粒度错误分析；归零法只能测到子集粒度。
5. **推理成本**：三图输入吞吐约 0.33 条/秒，为单图（2.34 条/秒）的 1/7，使"多模态输入"路线的验证成本显著升高。
