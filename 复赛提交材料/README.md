## 一、项目简介

### 1.1 任务

给定同场景的**可见光（visible）/ 红外（infrared）/ 深度（depth）**三模态图像与一条英文查询，
输出目标在**可见光图**中的归一化边界框 `[x1, y1, x2, y2]`（取值 0–1）。
评测指标 **ACC@0.5**：预测框与真值 IoU ≥ 0.5 记为该条命中。

复赛规模：**5690 条查询 / 1295 张图**（三模态各被引用 1295 张，缺失 0、损坏 0）。
其中**序数类查询 1103 条**（"从右数第二个"这类，占 19.4%），非序数 4587 条。

### 1.2 方案一句话

**不做端到端训练**：以开源大模型承担感知、以确定性规则承担推理。
Qwen3-VL 对非序数做直接定位、对序数查询启用 **Set-of-Mark 三段法**；
序数层再由**查询文本程序化推算**（水平轴 / 候选自排序 / 垂直轴 / 回退点四层叠加）；
最后经补框链保证零空框，硬约束校验后出件。

### 1.6 三条方法学结论（本项目最有分量的产出）

这三条都是**用线上提交的确定性得分**实测出来的，不是推测：

**① 先验能否迁移：**同机制（direct 框替换 direct 框）**可迁移**；跨机制**不可**。
「模型是否真升级」**不是必要条件**。

（★本条经过**两次自我更正**：初稿写"IoU 分布可预判升级/重掷"，被实测推翻（见下）；
第二稿写"必须**同时**满足『模型真升级』与『同机制』"，被跨代换模型那次实测再次推翻。）

| 杠杆 | 被替换的那一层 | 模型更"强"？ | 是否同机制 | 改动面 | 实测净成功率 |
|---|---|---|---|---|---|
| 非序数 32B 重跑 | 8B 直接框 | 8B→32B ✓ | ✓ | 467 | **+17.6%** |
| 序数层同机制替换（B′） | 8B 直接框 | 8B→32B ✓ | ✓ | 87 | **+16.1%** |
| AWQ→bf16 精度修复 | 32B-AWQ 直接框 | 同族 ✓ | ✓ | 111 | **+9.9%** |
| **跨代换模型（Qwen3.8-27B）** | 32B 直接框 | **未证实**（27B < 32B、跨代、无接地指标） | ✓ | **519** | **+19.4%** |
| 同模型三模态输入（D） | 32B 直接框 | 32B→32B ✗ | ✓ | 128 | **−3.1%** |
| 序数层 SoM | 8B 直接框 | 8B→32B ✓ | ✗ 跨机制 | 66 | **−10.6%** |
| VLX-Seek 替换非序数 | 32B 直接框 | ✗ | ✗ 跨机制 | 846 | **−18.4%** |

**修正后的判据（三条）**：

1. **同机制是必要条件**：跨机制在本项目 **5/5 全负**（SoM −10.6%、VLX −18.4%）。
   ⇒ **"可迁移的不是规则文本，而是被替换那一层的性质"**。
2. **"模型真的更强"不是必要条件**：Qwen3.8-27B 参数更小（27B < 32B）、属跨代新架构、
   官方 benchmark **无任何视觉接地指标**，事前被判定"先验不可迁移、不给正数、不是到 0.8 的路径"，
   实测 **+19.4%（8.8σ）**，是全部四次同机制测量中**最高的一次**。
3. **真正起作用的是**「**框层性质相同 ＋ 新模型的框与原层足够不同**」——
   差异本身就是收益来源（该件改动面 519，是 bf16 那次的 **4.7 倍**）。

**方法学教训（同时是本次的主要"不足之处"）**：事前拿"官方有没有接地指标"当
"模型是否更强"的**代理**，该代理在本件上失效。**证伪一个先验的成本是一次全量，
但把它当成"不发车的理由"，就直接丢掉 101 条。**
（须强调：本次是"事前判断偏保守"，**不是**事后调阈值——所有判据仍事前写定；
且不得由此反推"先验无所谓"，样本仍少。）

**被撤回的第一版说法**：曾据"IoU 分布"预判升级/重掷。直接复算 B′ 自身的改动剖面后，
该前提不成立——B′ 的 p50 = **0.000**、<0.3 占 **89.7%**，与 D 的 80.5% 几乎相同，
**结果却一正一负** ⇒ **IoU 剖面在本项目数据上没有区分力**。
（2026-10-03 又把该剖面对 bf16 件与 q38 件做过一次同口径对照：两者几乎同分布、结果皆为正，
进一步确认该判据无区分力。）上表是 **7 个数据点的归纳，样本仍少，仅作假设，不作承诺**。

**② 两类负面的破坏力量级不同，不可混为一谈**

| 负面类型 | 实测幅度 |
|---|---|
| **重掷**（把答案换成另一个独立猜测） | **−3.1%**（≈ 掷硬币略偏负） |
| **用新外部证据合成候选表**（连正确候选一起丢掉） | **−10% ~ −25%**（−24.8% / −18.6% / −23.1% / −10.6%） |

**重掷不毁掉已有正确答案，只是把它换掉**；后者会毁掉正确的候选。

**③ 分层小样是"改动率"的精确估计器；前缀不是**

| 指标 | 分层小样（300 条）预测 | 全量（1652 条）实测 |
|---|---|---|
| 改动率 | 0.077 | **0.077** |
| 与基线一致率 | 90.2% | **89.8%** |
| 输出 `[]` 率 | 4.3% | **4.3%** |

对照：按**图名排序的前缀**外推曾把改动面高估约 10%。
⇒ **关键是抽样方式（分层随机），不是样本量。**

**交付件阶段的起服要点（实测踩坑，已在 `code/remote_shell/_get_serve_q38.sh` 固化）**：

1. `--disable-custom-all-reduce`：本组合（cu130 + A100 cc8.0 + 驱动 580）下
   custom all-reduce 内核在 CUDA graph 捕获阶段崩（`custom_all_reduce.cuh:455 'invalid argument'`
   → TP1 死 → `Engine core initialization failed`）。拓扑与 P2P 均正常，故非硬件问题；
   退回 NCCL 即可。这不影响提示词/解码/并发（单变量前提不受影响）。
2. `--limit-mm-per-prompt '{"image":1,"video":0}'`：否则编码器按"最大尺寸视频"探测，
   一次性分配 5.77 GiB 而 OOM。
3. `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`：缓解碎片。
4. flashinfer JIT 需要 nvcc 与 dev 符号链接：pip 版 CUDA 只装 `libX.so.N` 而不装 `libX.so`
   ⇒ `-lcudart` 找不到；需批量补 `libX.so → libX.so.N` 并把 pip CUDA 链到 `/usr/local/cuda`。

## 六、注意事项

### 6.1 关于数据集与权重

- **数据集图像与模型权重均不入包**（大文件）。仅 `queries/queries.json` 随包（1.2 MB），
  供校验器离线自校验；其内容本就逐条内嵌在结果文件里（四字段回显），不构成额外披露。
- 复赛**未提供 `test.json`**，键集只能取自 `queries.json`。本方案不凭"应与初赛同构"的假设，
  而是以初赛提交件实测验证"提交件键集 == queries 键集 == test 键集"三者相等后才采用。

### 6.2 关于包内代码的一处改动（如实声明）

工作区中每个脚本都硬编码了本机绝对路径 `d:\Desktop\2026AiC`。打包时**仅做路径可移植化**：

- 把该字面量替换为 `ROOT`（`AIC_ROOT` 优先，缺省为 `code/` 的上一级）；
- 在每个脚本头部注入 8 行路径解析（`_HERE` / `ROOT` / `ROOT_S`）；
- `R / "某脚本.py"`（`subprocess` 调用同目录脚本）改为 `_HERE / "某脚本.py"`。

**算法逻辑一行未改**，可用 `diff` 逐文件核对（改动全部落在头部注入块与路径字面量处）。
打包脚本可重跑且会逐文件报告改动。

### 6.3 关于可复现性的边界（重要）

- **离线段 ✅ 可逐字节重建**：预处理、规则层、装配、校验均确定性，已实测
  （核心词表逐条重建、加轴后初赛归档件 9555 条 bbox 零差异、各层产物跨运行 ZIP SHA 相同）。
- **推理段 ❌ 不保证逐字节重建**：GPU 推理用 `bfloat16` + `device_map` / 算子调度，
  浮点归约顺序随硬件、驱动、库版本变化；即使代码与权重完全相同，产出也可能有少量差异
  并向下游传播。故本包记录**实测环境**（`env_record.txt`）而非断言可无限复现。

### 6.4 已知坑（复现者可直接避让）

1. **transformers 必须 < 5.0**。vLLM 0.11.0 配 transformers 5.x 会在启动时抛
   `Qwen2Tokenizer has no attribute all_special_tokens_extended`（5.x 移除了该属性）。
   实测 `4.57.6` 可用。
2. **GroundingDINO 的 `--half`（FP16）不可用**：MSDeformAttn 的 PyTorch 回退不支持 fp16，
   会全量报 `invalid dtype for bias`——表面耗时骤降，实为快速失败。
3. **面积守卫 `MAX_AREA = 0.35`**：超过即视为"合并多个目标"的宽框而拒绝采用。
   该守卫被全量数据两次检验（潜在损失仅约 16–20 条，其中约两成本就是同一个框），故**不放宽**。
4. **新版 PIL 不容忍逆序矩形**（`x1 > x2` 会抛 `ValueError`）。主管线 `draw_som` 已对
   **绘制用**矩形做角点排序；候选表与编号映射不经过该处，**机制未变**。
5. **覆盖率优先**：模型对约 9% 的条目输出空数组（认为图中无该物体），
   这类条目**必须保留基线框**——留空必然错，基线框至少还有猜中的机会。
6. **不要随意改写提示词常量**：本项目三次"引入新外部证据"的尝试全部为负
   （−24.8% / −18.6% / −23.1%），成功的杠杆只需"正确候选表 + 框几何"。
   故复现时**不要**改写 `code/_fuse_qwen.py` 与主管线中的三个提示词常量。
7. **"同机制"是可判定条件，不是感觉**：本项目实测教训是「**可迁移的不是规则文本，
   而是被替换那一层的性质**」。替换前请先算一次 `IoU(基线, 拟替换来源)`。
   下面这组对照**模型相同、层相同、改动量级相近**，差别只在机制：

   | 机制 | 被替换层的性质 | 改动面 | 实测净翻 | 净成功率 |
   |---|---|---|---|---|
   | **同机制** | 8B direct → 32B direct | 87 | **+14** | **+16.1%** |
   | **跨机制** | direct 基线 → SoM | 66 | **−7** | −10.6% |

   同机制替换的可用常数（**四次独立测量**）：**≈ +12% ~ +19% × 改动面**
   （467 → +82 = 17.6%；87 → +14 = 16.1%；111 → +11 = 9.9%；**519 → +101 = 19.4%**）。
   跨机制则本项目 **5/5 全负**（含一次约 6σ）。
   **但注意**：上表"模型是否更强"那一列**不是必要条件**——第四次测量的被替换层
   只满足"同机制"，模型反而更小、无接地指标，仍拿到全部四次中最高的一次（19.4%）。
   ⇒ **判据只用"同机制"这一条**；"模型更强"可作为**加分项**，不可作为**否决条件**。

8. **数据集有"两个格式子群"，赛题文档只描述了其中一个**（★这条不踩会整批丢分）：
   被引用的 1295 张图中，**1198 张**属 1920×1080 的 `.png` 组（深度 `I;16` 单通道 uint16、
   毫米、实测 0–19999），**97 张（7.5%）**属 640×360 的 `.jpg` 组（深度为 `RGB` 三通道
   且**逐像素相同**，实为 **8 位灰度**；JPEG 有损、原始 16 位量程不可还原）。
   直接把 3 维数组交给 `Image.fromarray(arr, mode="L")` 会抛
   `ValueError: Too many dimensions: 3 > 2`，**使那 97 张（7.5%）整批失败**。
   `code/_qwen_full_pipeline.py` 的 `load_depth()` 已按两组合并处理；对 `.jpg` 组
   **直通原值、不按未知比例缩放**——赛题语义只需"越亮越远"的**单调性**，8 位原值已满足，
   按未知比例换算成毫米等于凭空造信息。零回归已验证：`.png` 组新实现与旧规则输出**逐位相同**。

9. **派生读数必须把锚点与基线件的"阶段"对齐**（★踩过一次）：
   归零法的序数锚点（689）是在 **0.7766 阶段**测出的；若基线已是更高分的件
   （如 0.7963），序数层正确数可能已经变了，**沿用旧锚会算出矛盾的读数**。
   每次换基线都要重算锚点，并在脚本里写成硬断言（例：`_measure_zero_sup646_q38.py`
   用的就是 `N_ORD_CORRECT = 689 / N_NONORD_CORRECT = 3842` 这一对）。
   同理，`_assembly_32b.py` 的三个读数参数（`--base-score / --ord-correct /
   --base-correct`）必须与该次的基线件匹配。
