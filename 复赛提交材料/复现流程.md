# 复现流程手册 · 从数据到答案 zip

> **目标**：用同一套**方法论**重建出交付件 `result_semi_q38_nonord.zip`（线上 **ACC@0.5 = 0.7963**）。
>
> **复现的判定标准是"方法论一致 + 量级一致"，不要求字节级相同**（原因见 §1.3）。
> 只要流程、判据、参数一致，得到的分数应当落在同一量级（±几十条）；若显著偏离，说明某一环没对齐。
>
> 本文档面向复现者（评审 / 队友 / 未来的自己）。所有命令均**实测跑通**，参数为实际值。

## §0 先选路径：两条复现路线

| 路径 | 起点 | 需要重跑 | 耗时/资源 | 适用 |
|---|---|---|---|---|
| **甲 · 最短复现（推荐先做）** | 随包基线件 `submission_zips/semifinal/0.7786/result_semi_n32bf16_nonord.json` | **只有最后一级**（跨代换模型） | 1 次模型下载 + 约 2 小时 GPU | 验收方法论、核对量级 |
| **乙 · 全链复现** | 原始数据集 | 全部 6 级 | 多次模型下载 + 多轮 GPU（数十小时） | 从零验证整条链 |

**建议顺序**：先做**路径甲**（能立刻验证"换模型 + 装配 + 读数"这套方法论是否成立），
再做**路径乙**中自己关心的那几级。

> ★**路径乙的完整流程见 §5，其中有两级可以完全离线复算**：
> `L2`（序数层确定性规则链，0.7552→0.7598）与 `L4`（序数层同机制替换 B′，0.7766）
> 所需的**全部输入产物都随包**，**零 GPU、零下载**即可复算并核对。
> 想低成本验证"序数规则层"与"同机制替换"这两套核心判据，就从这两级开始 —— 见 §5.0 依赖图。

> 为什么路径甲是合法的"宏观复现"：本方案的交付件**是在既有基线件之上做单变量替换**得到的
> （只改非序数层，序数层逐位不动）。随包已经把所有中间基线件按得分归档，
> 所以"从基线件出发重跑最后一步"与"从零重跑整链"在**方法论上是同一件事**，
> 差别只在前面几级的产物是重算还是复用。

## §1 复现标准

### 1.1 什么必须一致（否则不是复现）

1. **提示词逐字一致**（见 §7.1）——提示词差异会与模型差异混在一起，无法归因。
2. **解码一致**：`temperature=0.0`（贪心）、`max_tokens=256`。
3. **并发一致**：`QWEN_CONC=8`（与交付件同）。
4. **几何守卫一致**：`MAX_AREA=0.35`、`MIN_AREA=1e-5`、`IOU_KEEP=0.5`（见 §7.3）。
5. **作用域判据一致**：只动"非序数 4587 条"，序数 1103 条**逐位不动**（脚本有硬断言）。
6. **方法论纪律一致**：§6 的五条。

### 1.2 什么可以不同

- 模型权重可从任意镜像下载（**校验逐分片 SHA256 即可**，见 §3.3）。
- 机器/驱动/框架小版本可不同（但 vLLM 有**下界**要求，见 §2）。
- 中间产物的**顺序**可以不同（脚本支持断点续跑）。

### 1.3 为什么不能保证字节级相同（如实说明）

- **离线段（CPU）**：确定性，**可逐字节重建**（几何原语、规则层、装配、校验均无随机性）。
- **推理段（GPU）**：不保证。`bfloat16` 下的浮点归约顺序随**硬件、驱动、cuDNN/flash-attn 版本**变化；
  即使代码与权重完全相同，产出也可能有少量坐标差异并向下游传播。
  **本项目实测过同类现象**：同条件复跑曾出现 4/30 条坐标差 0.001 的抖动（复跑即消失）。
  ⇒ 故本手册的验收标准是**"分数同量级 + 各级改动面同量级"**，而不是 SHA 相同。
  （交付件自身的 SHA256 见 `README.md` §6.5，用于确认"你手上的就是那一份"，不是复现目标。）

### 1.4 验收指标（怎么判断复现成功）

| 级别 | 指标 | 期望 |
|---|---|---|
| 单条推理 | 抽样 20 条与随包产物比对 | 大多数逐位相同；少数 IoU ≥ 0.99 |
| 改动面 | 装配器打印的 `★改动` 条数 | 与 §5 各级给的历史值同量级（±20%） |
| **总分** | 线上 ACC@0.5 | 与历史值差 **±0.005 以内**（≈ ±30 条）视为成功 |

### 2.1 三套环境（互不通用）

| **B2 推理**（**交付件级**） | Qwen3.8-27B / Qwen2.5-VL-72B | `vllm==0.23.0`、`torch==2.11.0+cu130`、`transformers==4.57.6` | **2×40 GB**（TP=2） |

### 2.2 硬性版本门槛（不满足直接起不来）

1. **`transformers` 必须 < 5.0**。5.x 移除了 `Qwen2Tokenizer.all_special_tokens_extended`，
   启动即抛 `AttributeError`。实测 `4.57.6` 可用。
2. **交付件级模型需 `vLLM ≥ 0.22.1`**：`Qwen3_5ForConditionalGeneration` 自该版本起登记在
   registry（本项目实测 0.22.1 / 0.23.0 / 0.25.1 均含；0.21.0 不含）。
   复核命令：
   ```bash
   python -c "from vllm.model_executor.models.registry import ModelRegistry as M; \
   print('Qwen3_5ForConditionalGeneration' in M.get_supported_archs())"
   # 期望 True
   ```
3. **A100 是 SM80**：vLLM 的 Online FP8 量化不支持（需 Ada/Hopper）⇒ 大模型只能用 AWQ/GPTQ。

### 2.3 包内路径解析

`code/remote_shell/*.sh` 是**远端脚本**，路径本来就是 `/root/rivermind-data`（跨机可解析性由

## §4 【路径甲】最短复现：从 0.7786 基线到答案 zip

### 4.1 起服务（交付件级）

```bash
# 远端脚本，含全部实测坑的处置（目录名断言 / TP 自动判定 / 权重完整性 / nvcc 与符号链接修复）
Q38_DIR=/root/rivermind-data/models/Qwen3.8-27B \
Q38_NAME=qwen38-27b \
Q38_MUST=Qwen3.8-27B \
bash /root/rivermind-data/_get_serve_q38.sh
```

**必须加的两个参数**（脚本已固化，手工起服时别漏）：

| 参数 | 为什么 |
|---|---|
| `--disable-custom-all-reduce` | `cu130 + A100(cc8.0) + 驱动 580` 组合下 custom all-reduce 内核在 CUDA graph 捕获阶段崩：`custom_all_reduce.cuh:455 'invalid argument'` → TP1 死 → `Engine core initialization failed`。拓扑与 P2P 均正常，退回 NCCL 即可。**不影响提示词/解码/并发** |
| `--limit-mm-per-prompt '{"image":1,"video":0}'` | 否则编码器按"最大尺寸视频"做探测，一次性分配 5.77 GiB 而 OOM（实测 budget 从 151250 降到 16384 tokens） |

另建议 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`（缓解碎片）。

**起服自证**（防起错模型——本项目把这条做成硬断言，因为起错模型会让读数完全无意义）：

```bash
curl -s http://127.0.0.1:8000/v1/models | python -c "import json,sys; d=json.load(sys.stdin); \
print([m['id'] for m in d['data']], [m['root'] for m in d['data']])"
#    期望 id 含 qwen38-27b；root 含 models/Qwen3.8-27B
```

### 4.2 闸门 G2 / G3（**全量前必过，不过即停**）

```bash
python code/_q38_gate.py --n 20 --out /tmp/_q38_gate20.json --vis-dir /tmp/q38_gate_vis
```

| 闸门 | 判据 | 处置 |
|---|---|---|
| **G2**（机检） | 20 条里 `bbox` 可解析 **≥ 16** | 不过 ⇒ 停（格式不兼容，别烧全量） |
| **G3**（**人眼**） | 框是否落在查询描述的目标附近：**≥12 通过**／**8~11 放行但登记"接地能力弱"**／**<8 停** | 见 `q38_gate_vis/_sheet.png`（4×5 拼版，一屏看完） |

> G3 必须是**人眼判据**：本项目的闸门要验的是"模型**能不能**接地"，不是"接得好不好"。
> 判据必须在**跑之前**定好（本项目把这三档写死在预登记里），**不得事后调**。

### 4.3 全量推理（非序数 4587 条）

```bash
QWEN_ENGINE=api32b \
QWEN_API_BASE=http://127.0.0.1:8000/v1 \
QWEN_API_MODEL=qwen38-27b \
QWEN_CONC=8 \
QWEN_PHASE=A \
QWEN_ONLY_NONORD=1 \
QWEN_DATA="$AIC_ROOT/复赛数据集-基于大模型的多模态视觉理解与推理" \
QWEN_CORES="$AIC_ROOT/_ordinal_cores_r2.json" \
QWEN_OUT_DIRECT="$AIC_ROOT/qwen38_direct.json" \
python -u code/_qwen_full_pipeline.py
```
- `PHASE=A` 只跑直接定位（交付件只需要这一相）；`QWEN_ONLY_NONORD=1` 只跑非序数。
- 支持断点续跑（每 50 条落盘一次），中断后原命令重跑即可。
- **产出健康度参考**（本交付件的实测值，用于中途判断是否跑歪）：
  `有框 92.8%｜输出 [] 7.2%｜框面积 p50 0.0131｜异常 0`；耗时 2.02 h。

### 4.4 装配出件（**读数三锚点必须对齐**）

```bash
python code/_assembly_32b.py --direct qwen38_direct.json \
    --base result_semi_n32bf16_nonord --base-score 0.7786 \
    --ord-correct 689 --base-correct 3741 \
    --stem result_semi_q38_nonord --zip
```

三个锚点的含义与**为什么必须一起改**：

| 参数 | 含义 | 本件取值 |
|---|---|---|
| `--base-score` | 基线件的线上得分 | 0.7786 |
| `--ord-correct` | 该阶段**序数层**的正确条数 | 689 |
| `--base-correct` | 该阶段**非序数桶**的正确条数 | 3741 |

> ★这三者是**同一阶段**的量，必须成套使用。本项目踩过一次：
> 序数锚点 689 是 **0.7766 阶段**测出的；若换成更高分的基线却沿用旧锚，
> 打印出来的读数公式就是错的（细节见 README §6.4 第 9 条）。
> 关系式：`0.7786 × 5690 − 689 = 3741`。

**装配器的六桶是互斥的，且带总和断言**（这是把"承诺"变成机器可检查的东西）：

```
1 无框 → 保留基线          模型输出 [] ⇒ 留空必错，基线框至少还有猜中的机会
2 框退化/逆序 → 保留基线
3 面积 >0.35 → 保留基线     视为"合并了多个目标"的宽框
4 面积 <1e-5 → 保留基线
5 与基线一致(IoU ≥ 0.5) → 不动
6 ★改动
断言：六桶之和 == 4587，否则直接失败
```
本交付件的实测桶分布：`329 / – / 100 / – / 3639 / 519`（合计 4587 ✓）。

### 4.5 硬约束校验（出件后的最后一道门）

```bash
python code/_validate_semi.py result/result_semi_q38_nonord.zip
#    期望：条数 5690 / 键集与 queries 一致 / 四字段原样回显 / bbox 全合法 ⇒ 退出码 0
```

### 4.6 读数（提交后）

```
非序数桶正确数 = 得分 × 5690 − 689        （对照基线 3741）
Δ = (得分 − 0.7786) × 5690
```
本交付件：`0.7963 × 5690 = 4531` ⇒ `C_非序数 = 4531 − 689 = 3842` ⇒ `Δ = +101 条`
（519 改动 ⇒ 净成功率 **19.4%**；零假设 σ=11.4 ⇒ **8.8σ**，不是噪声）。

## §5 【路径乙】全链复现（从数据到答案 zip）

> 本节是**完整流程**。全链 = **6 级 = 6 次独立提交**，逐级推进。
> 每一级给出：目的、输入、精确命令、输出、期望读数、校验点、失败定位。

### 5.0 ★ 先看依赖图：哪几级可以完全离线复算

**这张表决定你的工作量。** `L2` 与 `L4` 两级所需的一切产物**全部随包**，
**零 GPU、零下载**即可复算并核对；`L1 / L3 / L5 / L6` 需要重跑对应模型的推理。

| 级 | 产出件 | 线上分 | 该级输入 | 输入随包？ | 需 GPU |
|---|---|---|---|---|---|
| L1 | `result_final_semi` | 0.7459 | 数据集图像 + `Qwen3-VL-8B-Instruct`（LA 可选） | 图像/权重不入包 | ✅ |
| **L2** | `result_semi_ord_det` → … → `result_semi_enum_trunc` | 0.7552 → **0.7598** | `_semi_qwen3vl_all.json`、`_semi_qwen3vl_som_all.json`、`_enum_raw.json`、`_enum_targets.json`、L1 件 | **全部随包 ✓** | **❌ 纯 CPU** |
| L3 | `result_semi_n32_ordbase` | 0.7742 | 数据集图像 + `Qwen3-VL-32B-Instruct-AWQ` | 权重不入包 | ✅ |
| **L4** | `result_semi_n32_orddirect` | 0.7766 | L3 件、`_semi_qwen3vl_all.json`、`_qwen32b_direct_ord.json` | **全部随包 ✓** | **❌ 纯 CPU** |
| L5 | `result_semi_n32bf16_nonord` | 0.7786 | 数据集图像 + `Qwen3-VL-32B-Instruct`（bf16） | 权重不入包 | ✅ |
| L6 | `result_semi_q38_nonord` | **0.7963** | 数据集图像 + `Qwen3.8-27B` | 权重不入包 | ✅（2×40 GB） |
| **L7** | `result_semi_k72b_n519` | **待定** | 数据集图像 + `Qwen2.5-VL-72B-AWQ` | **产物随包 ✓** | 仅首次推理需 ✅（2×40 GB） |

**建议顺序**：先跑 **L2 → L4**（离线，立刻能验证两套核心判据：**序数规则层**与**同机制替换**），
再决定是否下载权重做 L1 / L3 / L5 / L6。

**方法论点（很重要）**：每一级都是"在上一级的件之上做**单变量替换**"，
且随包已把所有中间件按得分归档 ⇒ **你可以从任意一级的随包基线件接续，不必从 L1 从头跑**。

### 5.1 每一级的共同动作（套用四步即可）

1. **跑该级脚本** → 得到 `out` 字典（5690 条）
2. **看脚本自带的自检**（这些是 `assert`，失败即抛异常、**不会静默出件**）：
   - 分类桶**互斥**且总和 == 作用层条数
   - **序数层 1103 条逐位未动**（若该级只改非序数）
   - **非序数 4587 条逐位未动**（若该级只改序数）
   - 未提供证据的条目逐位未动
3. **出件并校验**：
   ```bash
   python code/_validate_semi.py <你的 zip>
   #    期望 4/4 通过、退出码 0
   ```
4. **提交 → 按口径读数 → 记入谱系**（`submission_zips/semifinal/SHA256.txt`）：
   ```
   提交分 = (该层正确数 + 其余层正确数) / 5690
   1 条 = 0.000176 分
   ```

> 平台按**历史最高分**记录 ⇒ **逐级推进无下行风险**（某级变差只损失一次提交名额）。

### 5.2 L1 — 8B 全量 + 补框链 ⇒ `result_final_semi`（0.7459）

**目的**：建立首个可用基线（8B 直接定位 + 序数 Set-of-Mark + 无框补链）。

**Step 1｜8B 两级推理**（需 GPU；引擎 `hf8b` = 本地 transformers 上的 Qwen3-VL-8B-Instruct）
```bash
QWEN_ENGINE=hf8b \
QWEN_MODEL=/path/to/Qwen3-VL-8B-Instruct \
QWEN_PHASE=AB \
QWEN_DATA="$AIC_ROOT/复赛数据集-基于大模型的多模态视觉理解与推理" \
QWEN_CORES="$AIC_ROOT/_ordinal_cores_r2.json" \
QWEN_OUT_DIRECT="$AIC_ROOT/qwen3vl_all.json" \
QWEN_OUT_SOM="$AIC_ROOT/qwen3vl_som_all.json" \
python -u code/_qwen_full_pipeline.py
```
- `PHASE=A` 全量直接定位（5690 条）；`PHASE=B` 序数层 SoM（**枚举 → 叠红编号 → 选号**三段）
- 产出：`qwen3vl_all.json`（直接框）、`qwen3vl_som_all.json`（SoM 选中框）
- **可省**：随包已含这两份产物（`_semi_qwen3vl_all.json` / `_semi_qwen3vl_som_all.json`）

**Step 2｜融合 + 补框链**
```bash
python code/_fuse_semi.py \
    --d8b _semi_qwen3vl_all.json \
    --s8b _semi_qwen3vl_som_all.json \
    --ir _semi_retry_ir.json \
    --retry19 _semi_retry19.json \
    --swap _semi_retry_thermal.json --swap-qids _semi_thermal_qids.json \

    --out result/result_final_semi.json --zip
```
- `--la`（LocateAnything-3B 补轮产物）**未随包**，可省；该步的净效果已体现在已归档的基线件里
- `--fill-full` = **覆盖率优先**：保证零空框（无框条目由确定来源补齐）
- 各补轮产物均为随包存档：`_semi_retry_ir.json`（换模态）、`_semi_retry19.json`（换问法）、
  `_semi_retry_thermal.json`（定向替换）

**期望读数**：非序数 **3648** + 序数 **596** = 4244 ⇒ `4244 / 5690 = 0.7459`
（序数层 596 由 `0.7459 × 5690 − 3648` 反推，与谱系里的外部交叉验证一致）

**校验点**：`_validate_semi.py` 4/4；条数 5690、键集与 queries 一致。

### 5.3 L2 — 序数层确定性规则链 ⇒ 0.7552 → **0.7598**（**纯 CPU，零 GPU**）

**目的**：序数层（1103 条，全项目最弱层）用**查询文本程序化推算**替代模型猜测。
四层叠加，**各层改动集互不相交**（所以可逐层出件核对，也可一次性给全）。

**机制**：
| 层 | 含义 | 改动面 → 净翻转 |
|---|---|---|
| `det` | 水平轴**文本推算**（从查询里的序数词推"第 k 个"该在哪） | 136 → **+53** |
| `selfsort` | 候选**自排序**（枚举候选按位置重排后再取第 k 个） | 41 → **+9** |
| `qfb` | **回退点改用直接框**（推算失败时不再用 SoM 选号，改用直接定位框） | 47 → **+3** |
| `yaxis` | **垂直轴**序数（上下方向的"第 k 个"） | 10 → **+3** |
| `trunc` | **枚举截断组修复**（枚举召回不足的条目换提示词重跑枚举并合并） | 52 → **+11** |

**命令（逐层，各出一个提交件用于核对）**：
```bash

python code/_variant_det_semi.py --which det --selfsort                 # → 0.7568
python code/_variant_det_semi.py --which det --selfsort --qfb           # → 0.7573
python code/_variant_det_semi.py --which det --selfsort --qfb --yaxis   # → 0.7578
```
**或一次性**（等价于上一步的最终状态）：
```bash

```
**第五层（枚举截断组修复）**：
```bash
python code/_enum_merge.py --trunc --zip-trunc --base result_semi_ord_det_ss_y_qfb
#    → 0.7598
```

**输入**（全部随包）：`_semi_qwen3vl_all.json`、`_semi_qwen3vl_som_all.json`、
`_enum_raw.json`、`_enum_targets.json`、`_ordinal_cores_r2.json`、基线件 `result_final_semi`。

**可选**：若要**重新采集**枚举原始框（而不是复用随包的 `_enum_raw.json`），
在 GPU 机器上跑 `code/_enum_retry.py`（无 argparse，靠环境变量
`QWEN_ENUM_OUT` / 数据目录驱动），产出即 `_enum_raw.json`。

**期望读数**：序数层 596 → **675**（净 +79，与五层之和 53+9+3+3+11 = 79 逐条吻合）；
总分 `(3648 + 675) / 5690 = 0.7598`。

**校验点**：每层脚本打印的桶分布互斥且合计 == 作用域；
`_enum_merge.py` 还会打印**保真度核对**（枚举合并是否改变了不该改的条目）。

**★ 本级的第一个坑：输出坐标空间与提示词不一致。**

判据（证据与脚本随包）：

修法：解析后按 `(W', H')` 归一化并裁剪到 `[0,1]` ⇒ 经 **`QWEN_BBOX_SPACE=smart_resize_px`**
注入管线。**该开关的缺省路径逐位不变**，故 L1–L6 的复现不受影响。

**起服**（复用同一套机制，只换 5 个 `Q38_*` 变量；`--disable-custom-all-reduce` 缺省已加）：

## §6 方法论纪律（**五条，复现时一并复现**）

这五条是本项目最有分量的产出，**不做这五条，复现出来的分数无法解释**：

1. **判据在跑之前写定**。作用域、闸门、事前预期、止损线，全部先写进预登记文件
   （本项目为 `_prereg_*.md`），然后再跑。**禁止事后调阈值**。
2. **单变量隔离**。每件只改一层，其余层**逐位不动**，并用**硬断言**（不是"构造上应该不动"）
   验证。这样得分差才能干净归因。
3. **归零法测量**。赛题不给真值，某子集的真实正确条数只能"测"：交一件把该子集框换成
   **必然错的角落小框**（面积 1e-4）的测量件，其余原样保留；平台按**历史最高分**记录
   （测量件不拉低成绩），返回的得分直接读出答案：
   ```
   得分 × 5690 = 序数层正确数 + 其余层正确数
   ```
   诱饵框必须**极小且贴角**——不能用整幅框（真值面积 ≥0.5 的条目会被误算为正确）。
4. **闸门先于全量**。20 条冒烟不过就不烧全量（G2 机检 + G3 人眼）。
5. **止损线先写**。例如"某方向 Δ ≤ 0 ⇒ 封口，记入族谱"。本项目据此关闭了多条全负路线。

> 另外一条重要的**血泪教训**：**"同机制"是可判定条件，不是感觉**。
> 跨机制替换（direct 基线 → SoM / 检测器候选）在本项目 **5/5 全负**（−10.6%、−18.4%）；
> 同机制（direct 框替换 direct 框）四次全正（9.9% ~ 19.4%）。
> 替换前请先算一次 `IoU(基线, 拟替换来源)`。

### 7.1 提示词（**必须逐字相同**，改动其一即不再是同一实验）

**非序数直接定位**（本交付件实际使用者）：

```

**序数枚举**（级 1 的 SoM 用）：

Detect ALL instances of "{core}" in the image. Output their bounding boxes as a JSON array of {"bbox_2d":[x1,y1,x2,y2]}, coordinates are integers 0-1000, ordered from left to right. Include partially visible ones.
```

**序数选号**（级 1 的 SoM 用）：

```
The image has {n} objects marked with red numbered circles (1 = leftmost, {n} = rightmost). Based on the numbering, which number corresponds to: "{q}"? Answer with ONLY the number.
```

## §9 已知坑速查（复现者可直接避让）

1. `transformers` 必须 `< 5.0`（见 §2.2）。
2. 交付件级模型需 `vLLM ≥ 0.22.1`（见 §2.2）。
3. **A100 上必须 `--disable-custom-all-reduce`**（见 §4.1）。
4. **必须 `--limit-mm-per-prompt '{"image":1,"video":0}'`**，否则编码器探测即 OOM（见 §4.1）。
5. flashinfer 的 JIT 需要 nvcc：pip 版 CUDA 只装 `libX.so.N` 而不装 `libX.so`
   ⇒ `-lcudart` 找不到。需批量补 `libX.so → libX.so.N` 符号链接，并把 pip CUDA 链到
   `/usr/local/cuda`（flashinfer 的默认回退路径）。
6. **数据集有两个格式子群，赛题文档只描述了其中一个**：被引用 1295 张里 **97 张（7.5%）**
   是 640×360 的 `.jpg` 组，其深度为 `RGB` 三通道且**逐像素相同**（实为 8 位灰度）。
   直接把 3 维数组交给 `Image.fromarray(arr, mode="L")` 会抛
   `ValueError: Too many dimensions: 3 > 2`，**使那 97 张整批失败**。
   对 `.jpg` 组应**直通原值、不按未知比例缩放**（赛题语义只需"越亮越远"的单调性）。
7. **新版 PIL 不容忍逆序矩形**（`x1 > x2` 会抛 `ValueError`）；`draw_som` 已对**绘制用**矩形
   做角点排序，候选表与编号映射不经过该处（机制未变）。
8. **覆盖率优先**：模型对约 7~9% 的条目输出 `[]`（认为图中无该物体），这类条目**必须保留基线框**
   ——留空必然错，基线框至少还有猜中的机会。
9. **别用"跑了一半的前缀"外推改动面**：按图名排序的前缀里分歧条目更密，会系统性高估约 10%。
   要估计改动面请用**分层随机小样**（实测 300 条分层随机：预测 0.077 / 实测 0.077，几乎逐位命中）。
10. **派生读数的锚点必须与基线件的"阶段"对齐**（见 §4.4）。
